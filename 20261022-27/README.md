# Iris Accord

A browser-local parametric **three-jaw radial fidget**. Turn a scalloped ring: three straight inclined slots gather or spread three sliding followers at once. This is a tactile mechanism, not a chuck or clamp. The new interaction differs from the earlier single-track sliders, linkage toys and coupled gears.

## Run and build

```sh
npm install
npm run dev
npm run predeploy
npm test
```

React + Vite, Three.js/OrbitControls, Manifold WASM solid modeling, fflate ZIP and Playwright validation. Dependencies are bundled locally, including WASM; no CDN, remote modeling API, account or key. Vite base is `/daily-app2/20261022-27/`. The app includes the requested `predeploy: npm run build`, `deploy: gh-pages -d dist` scripts. Public publication uses the **root monorepo deploy**, not the per-app deploy script.

## Mechanism and parameters

Seven closed, individually exportable parts: stationary palm base, fixed guide lid, turning ring, three independent radial jaws, and axle cap. Three base registration pegs seat into the lid. The cap seats on a narrow shoulder peg; it must not clamp the rotor. The lid retains jaw bodies while their pins pass through radial windows into the rotor slots.

For ring angle θ each slot centerline satisfies x−y=R in rotating coordinates. Each guided pin therefore follows **r=R/(cos θ+sin θ)**. The illustrated window is ±12°, giving approximately 10.5 mm radial travel at default R=23 mm. No independent angular hard stops are provided; do not force past the illustrated range. Default radial/axial clearance is 0.35 mm. Minimum lid wing overlap is 1.7 mm. The sampled window has positive inner/outer guide-end reserve and slot endpoint reserve throughout the allowed parameter space.

All dimensions are **millimeters**, except explicitly labeled degrees, percentages and grayscale threshold. Supported ranges:

| Parameter | Range |
|---|---|
| Neutral pin radius | 22–24 mm |
| Slider body length | 8–10 mm |
| Ring scallop depth | 0.4–1.2 mm |
| Running clearance | 0.25–0.50 mm |
| Palm tab radius | 7–9 mm |
| Palm groove depth | 0–0.5 mm |
| Press socket radial allowance | −0.08 to −0.01 mm |

The base floor is 2 mm; jaw bodies 3 mm; fixed lid 2 mm; rotor 3 mm. Minimum jaw bearing wing is 1.7 mm. Import geometry stays on the remote stationary tab at X=−52 mm, at least 4 mm clear of the main stationary enclosure and well outside the rotor. Surface grooves and imports never alter bearing fits. Three presets change actual dimensions, illustrated by thumbnails generated by the same modeling engine. Variations are bounded to supported ranges. Shape actions support undo/redo and portable JSON save/open.

## Image import: actual geometry, not a photo reconstruction

PNG and JPEG; **16 bytes–2 MB**, at most **12 megapixels**, maximum **6,000 px per side**. Header dimensions and content are checked before decoding. Images are normalized locally to at most 500 px on the longest side for bounded portable storage.

The user chooses contain/cover fit and ±25% crop shifts. A 20×20 locally sampled luminance grid uses Rec.709 coefficients. Transparent pixels are composited over white. Threshold mode assigns either zero or the selected depth to each grid vertex; grayscale mode uses depth×(1−luminance/255). Adjacent grid vertices are triangulated into a continuous height field on a closed 0.4 mm backing, and **Boolean-unioned** 0.15 mm into the stationary tab. A thresholded silhouette thus remains on a solid square backing; this is **2D-to-relief**, not automatic full 3D reconstruction from one photo. Relief depth is 0.4–3 mm; threshold 1–254. Empty results block export.

Source and exact conversion-grid previews are shown beside the final 3D model. Footprint is 4–7 mm, Z rotation ±180°, X shift ±1.5 mm, Y shift ±2 mm. A 6.5 mm radial safe-zone check rejects placements that escape the protected tab region. Relief and threshold controls measurably change the final binary STL. Replace, remove and reset are supported.

## STL import: strict, bounded integration

Both **ASCII and binary STL** are parsed locally, up to 2 MB / 1,500 triangles. Each source axis must span 0.2–250 mm with finite coordinates. STL carries no units: **explicit millimeter confirmation is required** before integration/export.

Input must be one connected, closed, outward-wound, positive-volume **convex solid with a broad flat bottom down in Z**, at least 25% bottom footprint and no overhanging XY projection. Vertex welding uses 0.00001 mm tolerance. Degenerate faces, open/nonmanifold edges, inconsistent winding, self-intersections, concavity, unsupported flat-base contacts, disconnected bodies, invalid dimensions and truncated data are rejected with guidance. No automatic repair is claimed or performed. Use a mesh editor to repair/reorient/decimate unsupported sources, then re-import.

XY is scaled proportionally to the requested 4–7 mm footprint; Z is independently fitted to 0.6–5 mm height. The fitted XY span must remain at least 1.2 mm. Centering, Z rotation and XY placement are editable and resettable. The mesh is sunk 0.15 mm into the tab and solid-unioned, replacing the built-in grip. The final base must remain one connected valid solid. This is real mesh-to-fidget integration, not an unchanged mesh re-export. Source dimensions, triangle count, format and a source 3D preview are shown. Only Z rotation is offered to preserve the verified support-free bottom contract.

## Files, privacy and recovery

All user data is processed inside the browser. No uploads or telemetry. Synthetic sample fixtures (`mark.png`, `waves.jpg`, `wedge-ascii.stl`, `gem-binary.stl`) are bundled, downloadable and usable by file picker or Try buttons; generated in-house, no third-party assets or attribution required. Personal files are not stored in the repository. Modeling/parsing runs in a local worker; complexity is bounded. Progress and recoverable errors disable export until valid.

Saving a design explicitly embeds the bounded normalized image and conversion settings or the verified mesh vertices/indices, so imports are actually restored on reopen. JSON limit 2 MB; imported mesh payload is revalidated. No missing-file restoration is simulated. History keeps at most 35 snapshots. Loading a bad file blocks export until replaced, removed or reset.

## Preview and export

Preview and export consume the **same generated final part geometry**. The assembled scene moves these rigid parts only; it never changes the printable meshes. Print layout is a separate nonintersecting bed-flat strip. Its X/Y/Z extents are displayed in mm, including individual-part extents when selected. The full strip is about 330×83×14 mm and may exceed your print bed: download individual parts or ZIP and arrange them in your slicer. Binary STL includes geometry only; preview palette colours are not stored.

Orbit, zoom and reset/fit work on desktop and touch screens. The slim header, large canvas, right control rail, five editor tabs and phone collapsible controls use warm sand/clay styling. Export stays fixed/reachable on phones. UX inspiration: https://vaseverse.org/ ; original fidget mechanism, branding, text and synthetic assets. No reference source/assets copied.

## Print and assembly

1. Calibrate the socket coupon on a Ø3.6 mm test peg first. Allowance gives 0.02–0.16 mm diametral interference, not a universal fit guarantee. Adjust to your printer/material; do not force.
2. Print broad flat faces down, pegs up; PLA or PETG, 0.4 mm nozzle, 0.16–0.20 mm layers, four walls. No supports intended. No hardware, magnets, bearings or compliant hinges.
3. Place all three jaws into their base guideways with pins upward. Press the lid evenly onto its three outer pegs, with jaw pins through radial windows.
4. Position the jaw pins at the neutral radius R. Lower the ring onto the axle and the three pin followers simultaneously into its slots.
5. Press the axle cap onto its shoulder peg, leaving the rotor running gap. Confirm the lid and cap are secure and the ring turns freely. Lift the cap/ring for service.
6. Gently turn within ±12°. Keep fingers away from pinch points; never force end travel. Small removable parts are not suitable for young children.

## Validation and limitations

`npm test` writes `geometry-validation.json`: default, all-min/all-max, all 128 parameter corners, three presets, eight deterministic variations; 24 image/STL cases across presets/extremes. STL files are parsed to check triangle counts, finite coordinates, nondegenerate faces, unit normals/outward winding, positive volume **per connected component**, mm bounds and two-face welded edge incidence. Seven parts must stay separate in print layout. Checks also cover slot closure, jaw separation, guide travel reserve, shoulder/lid retention, safe import placement and sampled true solid intersections over 25 ring positions. Only the two explicitly intended press-fit pairs (base/lid registration pegs and base/axle cap) are excluded from intersection checks.

`node browser-test.cjs`, `node extra-browser.cjs`, `node roundtrip-test.cjs` exercise real browser PNG/JPEG/ASCII/binary input, exported geometry changes versus baseline, transformations, replace/remove/reset, malformed/oversized/unsupported files, empty silhouettes, presets/variations, undo/redo, all portable import round trips, per-part STL/ZIP/coupon, source drag/drop, 320/390 px phone layout, touch orbit/pinch, reachable export and geometry-neutral colours. Browser exports are compared with the exact preview geometry signature and parsed for mesh validity. Further production/public smoke tests verify bundled worker/WASM and mobile exports. Evidence JSON and screenshots are retained alongside the app. Tests make no slicer-time estimates.

**Digital verification is not a physical print test.** Friction, cap/lid retention, durability and tactile feel must be checked on a real print. No physical print has been performed or claimed.
