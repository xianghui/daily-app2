# Validation — Skew & Saddle

Computational and browser checks; **no physical print, fit, material-strength or assembly tests**.

- `geometry-validation.json`: 42 cases covering three presets, three end profiles, individual parameter limits, combined limits, synthetic threshold/grayscale art and two real parsed STL fixtures with transformed variants. Every part, connected card and translated six-part plate is independently parsed from binary STL: finite vertices, nondegenerate triangles, normalized/winding-matched normals, opposite-directed edge incidence after 1e−5 mm welding, positive volume for each connected component, expected bounds and bed alignment.
- Each case also checks 15 assembled part pairs, 25 insertion heights × nine crossings, 18 complementary lap probes, 24 analytic saddle-edge probes, minimum backing/webs, bed support, packed-part separation, card inclusion and bounds. Simulated 24 runner cuts release six intended ribs plus carrier. Loose half-laps are explicitly not positively lift-retained.
- `assembly-validation.json`: actual Boolean probes prove a bright image hole remains unengraved, its dark surrounding ring removes material, continuous backing remains; incompatible narrow/short packing and out-of-zone transformed art are rejected.
- `browser-validation.json`: real production file-picker uploads, actual downloaded default, PNG/JPEG, ASCII/binary STL and min/max geometry. Pixel threshold, crop, depth, height mode, source shape/scale/rotation/placement affect STL. All downloads match preview signatures and Node regeneration of portable JSON; each imported result also passes part and assembly checks. Malformed, truncated, nonmanifold, open, concave, excessive triangle/byte/pixel inputs, invalid dimensions/transforms and empty silhouettes block export recoverably. Touch-enabled 390/320 px browser contexts exercise real orbit/pinch gestures and actual image/STL downloads. No off-origin file-processing requests or runtime errors.
- `studio-validation.json`: presets, silhouettes, text/searchable icon/SVG geometry, bounded image/STL JSON round trips, named saves/reload, missing-payload error, undo/redo, all views, real ZIP parsed per part, dark-theme persistence, keyboard focus, collapsible sections, desktop left 374 px rail and mobile preview-first layout, worker loading failure/recovery.
- `orientation-validation.json`: Z/Y/−Z source orientations and unit-confirmed final parts; source dimensions and exact mesh signatures match regeneration.
- `icons-drop-validation.json`: six original vector marks affect exported solids and pass identical mesh/assembly checks; real browser drag/drop image event.
- `rapid-validation.json`: delayed worker cannot enable export after a newer invalid edit; reset reproduces bytes; background polarity and spacing change geometry; each dedicated part button produces a valid matching STL download.
- `preview-validation.json`: screenshots differ for assembled/exploded/card/loose/isolated views, insertion lift and see-through material; imported control IDs are unique.
- `mobile-layout-validation.json`: every editor tab and expanded assembly instructions fit a 320 px viewport; real JSON download, SVG upload, reachable exports, reduced-motion preference, no runtime errors.
- `reference-measurements.json`, `reference-analysis.json`, `evidence/reference-sections.png`: actual downloaded mesh parsing/hash/component/interface measurements and explicit mapping to new geometry. Read-only local candidates were parsed and rejected for inappropriate topology; no private/raw reference STL bundled.
- `gallery-validation.json`: inline scripts compile via `new Function`, new STL entry exactly once/newest, all 343 old entries preserved unchanged, 344 rendered cards with STL category first and no runtime errors.
- `combined-browser-validation.json`: full import/export mesh and mechanism suite rerun under the root production `deploy/` base path, not Vite development mode.

Reproducible commands are in README. Reports contain bounded numerical evidence and synthetic sources only; screenshots capture the actual tested UI. Numerical collision/insertion/footprint probes are sampled checks, not a universal proof of fit, material behavior, strength or slicer behavior.
