# Cost Tapestry

A local-AI activity-based overhead worksheet for small workshop cost analysts. Distinct from price/volume attribution or break-even apps: it reconciles unstructured consumption notes to supplied activity pools, then allocates each pool's cost to products using reviewed drivers. No backend, account access, ledger writes or financial execution.

## Workflow and formats

1. Choose the synthetic furniture/print example, paste JSON or import a `.json` file. Supply `policies` (id, title, description, integer `cents`), `products` (id, title, positive integer output `units`), and `records` (id, free text, supplied `product` id, positive integer `driver`). All costs use one currency and all data one complete period. Drivers must have a common unit **within each pool**, e.g. setup counts, design hours or delivery counts. Driver units may differ between pools; their validity/completeness cannot be inferred.
2. Explicitly click **Load AI & match activities**. Real MiniLM embeddings propose each usage note's activity pool. AI does not extract numerical quantities, assert accounting truth or calculate savings. Review source snippets, alternative pool descriptions and cosine similarities (not confidence).
3. Correct pool/product/driver, add review notes and approve or hold every row. Undo restores the prior row review. Any row edit resets its approval; any review/settings change invalidates the applied export snapshot. Originals remain untouched.
4. Verify pool costs and product output, then **Apply reviewed allocation**. All rows must be reviewed. A held row blocks its whole linked pool; a pool without usage is also blocked. Correct the linked pool before holding a mislink. Blocked costs remain visible, not assumed zero. Approved rows in blocked pools retain null allocated costs.
5. Export reviewed JSON (full original input, settings, rows, pools, product comparisons), usage CSV (every row/hold), Products CSV (every product and baseline), or complete Markdown; copy Markdown is also available. CSV quotes multiline/comma content and guards formula-like text. Reimporting JSON restores **original inputs only**, never approvals or previous settings. Reapply after edits to export current reviewed values.

## Deterministic calculation

Each eligible pool's cost is allocated by summed approved driver units per product. Exact BigInt numerator/remainder arithmetic and Hamilton largest-remainder rounding preserve every cent. Ties follow product input order. Each product's pool share is then apportioned over its source usage rows; ties follow source input order. Thus product totals, row totals and pool totals agree. Source-row allocations are an audit breakdown, not incremental costs.

Baseline: allocate the **same eligible total overhead** by reviewed product output units, rounding with the same method. Product differences sum to zero. This is a descriptive comparison of allocation assumptions, not causal evidence, realized savings, forecast accuracy or improved profitability. Outputs exclude direct costs, unused-capacity separation, inventory valuation and pricing. Per-unit costs are ratios; display rounds currency to two decimals while JSON/CSV retains unrounded ratios and exact integer allocated cents. All-held inputs allocate zero and visibly block all supplied costs. Zero-cost pools are allowed; zero-driver rows and zero-output products are not.

## Real AI, runtime and privacy

- Model: [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0; quantized q8 ONNX, 384-dimensional normalized mean-pooled embeddings. [Upstream model](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2). Four-text batches, max 256 tokens per text; long text can truncate. Model revision follows the host's main revision; future host changes may affect output.
- Transformers.js **4.3.2**, Apache-2.0; ONNX Runtime Web, MIT (installed runtime version in lockfile). Worker bundled locally; module factory bundled at `runtime/`. Byte-identical ~27 MB WASM is shared from `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`; preserve that existing collection asset. Its SHA-256 is `49871f5a4409519797e127440868a6d1923339d9185907f301a5b2a1d90af082`.
- Initial download approximately **50 MB**: ~23 MB weights/tokenizer/configuration via huggingface.co / hf.co and CDN, plus ~27 MB same-origin CPU runtime. Internet needed initially. No model downloads until the explicit load button. Host receives normal download request metadata, not input notes. All default inference/content processing stays on-device; no provider keys, remote inference option, telemetry or hidden API calls.
- Current desktop Chrome is tested, requiring WebAssembly SIMD, module workers, Cache API and several hundred MB available memory. CPU/WASM is the default, **not an untested fallback**; WebGPU is unnecessary. Physical phones, other browsers and low-memory devices are unverified. Failures explain requirements and permit retry, never substitute fake AI.
- Worker source, WASM factory/binary and model files are cached. Tested offline scope: **fresh-worker real inference within an already-open, successfully warmed page** with browser networking disabled. Offline navigation/reload/app-shell installation is not promised. Cache storage may be denied or evicted; then internet is required again. Clear this site's browser storage to remove downloaded cache data. Inputs/reviews are memory-only; export to retain your work.
- Cosine retrieval does not understand accounting equivalence reliably. Negation and unrelated notes can receive incorrect nearest-pool suggestions. Every row requires approval/hold; inspect completeness and driver validity yourself. Imported instructions are text data and cannot request credentials or gain tool authority.

## Limits and errors

2–6 pools, 2–6 products, 1–24 records; IDs unique within each list, 1–40 characters. Titles ≤80; descriptions/source texts ≤400; original JSON ≤24,000 characters, imported file ≤1 MB. Pool costs integer cents 0–100 million, output/driver units integers 1–1 million. JSON export envelopes can be reimported if below 1 MB. Unsupported files/empty/bad JSON, invalid IDs/numbers and oversized batches are rejected. Finite normalized 384-vectors are validated before suggestions. Worker/network failures, unsupported runtime, malformed vectors and 180-second timeout yield no AI results. Cancel terminates the worker. Input changes, delayed imports/downloads and late worker messages use run identities so older work cannot overwrite new work.
