# Yield Ledger

A private rework-prioritization desk for quality coordinators. Messy defect narratives are the bottleneck: local semantic inference proposes a shared defect family, then mandatory human review feeds a transparent Pareto investigation checklist. This is not a root-cause detector, automatic quality decision, defect extractor or savings forecast.

## Use

1. Choose a synthetic Furniture/Print shop example, paste a JSON manifest or import `.json`. Define 1–6 mutually exclusive families (`id`, `title`, `description`) and 1–24 disjoint batches (`id`, `text`, positive integer `count`, nonnegative integer `lossCents`). Supply `name`, `metric` (`count` or `lossCents`) and integer `target` (50–100). Examples in `src/core.js` are the schema reference.
2. Confirm a single complete time window and currency; counts represent affected units counted once. `lossCents` is **total batch loss**, not unit loss. Multi-defect or overlapping batches must be reconciled before import. AI does not validate these business assumptions.
3. Click **Load AI & propose families**. Before this explicit action no model requests occur. Observe downloads and four-text inference batches; cancel terminates the worker. Retry is explicit and never falls back to synthetic AI.
4. Inspect original snippets, ranked family definitions and cosine similarities. Change the family, count, total batch loss or reviewer note. Any edit resets approval and invalidates applied exports. Approve or hold every batch. Undo restores the preceding review state (up to 100 edits). Original input is never mutated.
5. Choose count or loss coverage and a target. Apply the reviewed priorities. Any held batch blocks the entire ranking; its complete audit is still exportable. Zero-valued metric families remain in the audit, not the priority ranking. A zero total produces zero priorities.
6. Export current **JSON**, **CSV**, **Markdown**, or copy the checklist. JSON includes full originals, review, all families, totals, computed metrics and method. CSV contains every source batch with original/reviewed counts and cents and priority status; it is not merely the selected subset. Formula-like string cells are apostrophe-escaped, while numeric columns remain numbers. Markdown includes priorities and every batch. JSON re-import restores **original inputs only**, requiring a new run and fresh approvals; it does not silently trust saved decisions. CSV/PDF import is unsupported.

## Actual AI and deterministic boundaries

- Model: [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, quantized q8 ONNX. Model registry uses its current main revision (not an immutable revision); the lockfile pins the installed runtime, not remote weight updates.
- Runtime: `@huggingface/transformers` 4.3.2, bundled module worker, ONNX Runtime Web WASM CPU, one thread. Normalized mean-pooled 384-dimensional learned embeddings compare each record with the supplied family descriptions. No WebGPU, API key, server or paid service. Cosine ranks candidates; **not confidence**. There is always a nearest family even for unrelated data—hold such records.
- Vector shape, count, finiteness and near-unit norm are validated. Four texts/batch, first 256 tokens/text, descriptions ≤400 characters, input originals ≤24 KB, 180-second timeout. File/export JSON import ≤1 MB. Model errors, worker construction/errors, network errors and invalid output leave no invented recommendations. Run identity guards input changes, late responses, delayed imports and cancelled downloads.
- After review, exact bounded integer sums conserve counts and cents. Nonzero families are ranked descending by the chosen metric. Take the smallest **descending prefix** meeting the coverage target and include every family tied at its cutoff. This is not minimum-cardinality arbitrary subset selection. Alphabetical baseline takes the same number of nonzero families by title (English locale); percentages measure actual dataset share, not estimated time saved, AI accuracy or future improvement. Ties within ordering use family IDs. No 80/20 distribution is assumed.

## Downloads, static hosting and privacy

First explicit load requires internet and roughly **50 MB**: ~23 MB model/tokenizer files from `huggingface.co`, `hf.co` and their CDN (observed `us.aws.cdn.hf.co`), plus ~27 MB local CPU runtime. Browser memory can require several hundred MB. Use current desktop Chrome with WebAssembly SIMD and module workers. CPU is the default, not an untested GPU fallback. Physical phones, Safari/Firefox/Edge and low-memory devices are unverified. Unsupported devices get an actionable error, not fake inference.

Input stays in browser memory; downloaded model files are not content uploads. No telemetry, content POSTs, external tools, keys or optional remote provider. Imported instructions remain data. Cache API stores worker source and CPU module factory/binary, while Transformers.js caches model files. Worker loading bridges cached source/factory through local blob modules. After a successful run, a **fresh worker in an already-open warmed page** was tested with all network disabled. Offline app reload/navigation is **not promised**; caches can be disabled, evicted or invalidated by a new release. Download/export files are user-controlled local artifacts and may contain their original data.

The byte-identical WASM binary is reused at `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm` (SHA-256 `49871f5a4409519797e127440868a6d1923339d9185907f301a5b2a1d90af082`). Preserve this older build in the collection. The worker, JS, CSS and WASM module factory are bundled/hosted locally. Vite base is `/daily-app2/20261111-8/`. Per-app deploy scripts exist by contract but **publish only through root** `npm run predeploy` / `npm run deploy`, which retains the whole collection.

## Observed limits and validation

See [VALIDATION.md](VALIDATION.md) and machine-readable reports. Tiny known-answer fixtures matched 5/6 furniture notes and 6/6 print notes; one lacquer defect mentioning arrival was wrongly assigned to packaging. Tests deliberately correct it in review, retaining the original AI proposal. An unrelated adversarial note also got a nearest family and was held. Maximum batches repeated the same furniture confusion. Semantic similarity is not cause, safety, completeness or business-identity verification.

The deterministic portion passed 2,100 independent subset-oracle cases constrained to descending/tie-closed prefixes. Real production-browser inference, all-network-off fresh workers, downloaded artifact parsing, review/undo/holds and fault-injected defensive paths were exercised. Fault injection is used only for errors/stale guards, never successful AI claims. Responsive browser viewports are not physical-device tests. No prediction, universal accuracy or guaranteed cost reduction is claimed.
