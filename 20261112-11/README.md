# Share Tapestry

Private shared-expense reconciliation for community outing and studio coordinators. Real local semantic AI proposes who paid from informal payer notes; mandatory human verification feeds exact-cent weighted sharing and a net settlement worksheet. It never sends money or connects to an account.

## Workflow
1. Load **Community outing** or **Studio weekend** (synthetic), paste JSON, or import JSON. Supply a roster `catalog` of `{id,title,description}`, `name`, one `currency`, and `records` of `{id,text,qty,weights}`. Each `text` describes the **payer**, not every participant. `qty` means integer cents, not dollars. Each `weights` object has every roster ID: 1 each means equal sharing, 2 means twice a share, 0 excludes someone. Example 1001 cents across four equal participants gives 251,250,250,250 cents in roster order.
2. Explicitly click **Load AI & reconcile reports**. Real MiniLM embeddings compare payer notes with supplied person descriptions, returning ranked candidates and cosine evidence. This reduces manual identity reconciliation when words differ. There are no hardcoded responses or heuristic fallback. AI does **not** extract amounts, identify beneficiaries, authenticate payers or verify facts. Imported instructions are inert model data.
3. Review **every** payer, cents and share weight. Correct, approve or hold; add notes and undo edits. No fabricated confidence. Input edits cancel/invalidate processing; review edits invalidate applied exports. Reimport of audit JSON restores original inputs only, never prior approvals.
4. Apply. Any hold blocks the **entire** settlement: an unknown expense can change everyone's balance. For fully approved data, integer largest-remainder allocation conserves every cent. Fractions are ranked by exact integer remainders; roster order breaks ties. Paid minus allocated share gives each participant's net; positive means receives. Greedy largest-debtor/largest-creditor transfers clear balances. It is deterministic netting, **not** guaranteed minimum payment count or a financial/accounting certification.
5. Compare the **same reviewed expenses** under direct per-expense reimbursements (each beneficiary pays their share to that payer) with netting. Counts and total cash moved are computed, not measured time or accuracy gains. Download complete JSON (originals, reviews, allocations, balances, transfers), expense-audit CSV, Markdown with transfers/balances and every expense, or copy that Markdown. No external actions occur.

## Model/source/license/runtime
- [`Xenova/all-MiniLM-L6-v2`](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, quantized q8 ONNX. English feature extraction, normalized mean-pooled 384-dimensional vectors; finite shape/count/norm validated before ranking.
- Transformers.js **4.3.2** (Apache-2.0), ONNX Runtime Web (MIT), **WASM CPU**, no WebGPU or API key required. Four texts per batch, 256-token context with truncation. Similarity is not identity/equivalence; names, negation, unrelated notes and similar roles can fail. Tiny fixture success is not population accuracy. A negated payer challenge mislinked to the gardener instead of the mechanic: human verification is necessary.
- Before explicit loading the app discloses **~50 MB first download**: ~23 MB public model/tokenizer from huggingface.co / hf.co and model CDN, ~27 MB same-origin WASM. Local app code, bundled module worker and WASM factory. Reuses byte-identical immutable collection WASM at `../20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm` (26,861,777 bytes; SHA-256 `49871f5a4409519797e127440868a6d1923339d9185907f301a5b2a1d90af082`). Preserve that asset.
- Requires modern module workers and WebAssembly SIMD; several hundred MB free RAM recommended. Desktop Chrome tested; physical mobile devices, low-memory performance and other browsers untested. No universal-phone performance claim.

## Privacy, caching and recovery
No shared/user API credentials, backend, analytics or remote AI integration. Browser content stays in memory on-device; only public model/runtime assets download. Request capture tests check GET-only asset traffic, no content in URLs/bodies and no model host access before explicit load. Model revisions are upstream public main, not pinned; upstream changes may affect future results. Cache API stores public worker/factory/WASM, and Transformers.js stores model files. No app-initiated content storage.

Real **fresh-worker offline inference was tested inside an already-open, warmed production page**. Offline reload/navigation/app-shell startup is **not supported or promised**. Eviction/private browsing can require redownload. Progress, cancel and retry are visible. Cancel terminates worker and run IDs suppress stale results, worker-download fetches and file reads. 180-second timeout; model network, unsupported runtime, worker, invalid input and malformed embedding failures show errors, never fake output. Failed/cancelled downloads may leave public assets cached, not expense content.

## Limits / formats
2–8 people; 1–24 expenses; unique safe IDs ≤40 characters; titles ≤80; descriptions/notes ≤400; `qty` positive safe integer cents ≤1,000,000 per expense; weights integer 0–100 with at least one positive per expense. Original JSON ≤18,000 characters; JSON audit/file import ≤1 MB. Supported two-decimal currencies: USD, EUR, GBP, SGD, AUD, CAD. No currency mixing/conversion, refunds, negative expenses, taxes, bank details or remote payments. Review transfers manually with participants. JSON input only; CSV/PDF/images unsupported. CSV formula-like text is apostrophe-protected and multiline quoted. All original people/expense records survive JSON, even holds; settlement lists every participant including zero balances.
