# Tally Quay

A local-AI stocktake reconciliation and recount worksheet for storekeepers. Distinct from inventory purchasing/ABC tools: this compares reviewed physical counts with a book snapshot, blocks duplicate bin counts and exposes offsetting shortages/excess.

## Workflow
1. Load either synthetic example, paste JSON or import `.json`. Set a single snapshot, currency, unit per product and `toleranceUnits` in JSON. Catalog entries contain `id,title,description,expected,unitCents`. Count lines contain `id,text,bin,qty`. Zero physical counts are valid. Costs are integer cents.
2. Explicitly click **Load AI & reconcile reports**. Real MiniLM embeddings rank your catalog descriptions for each note. No exact-match/regex/demo fallback. Cosines are evidence, not confidence or proof of identity. Imported instructions remain data; no tool execution.
3. Verify each proposed product, bin and whole-unit quantity. Expected ledger quantities and unit costs are editable in the original JSON (rerun required). Approve or hold each line and add notes. Undo reverses review edits; originals remain immutable. Every edit invalidates applied exports.
4. Apply the worksheet. Approved bin counts aggregate by product. Duplicate product/bin pairs (trimmed and case-insensitive), missing counts or assigned holds block a product's variance release. A hold only blocks its assigned product: uncertain identity or missing source coverage requires resolving the entire worksheet before use. The app cannot detect omitted bins or overlapping partial counts with different bin names.
5. Review the recount list. Products above the chosen absolute unit tolerance or with unresolved counts need attention. Compare absolute net variance with the sum of absolute product variances; netting can conceal opposing errors. These are computed descriptive totals, not measured accuracy/time improvements. All released products use the same basis. Bin-specific expected quantities are not supplied, so bin-level offset errors cannot be measured.
6. Download complete JSON/audit CSV/Markdown or copy Markdown. All records, holds and originals survive JSON. CSV includes original and reviewed bin/counts. Markdown includes every line and product. JSON audit reimport restores originals only and requires fresh AI/review. No stock postings, purchases or account changes.

## Real AI, runtime, license
- `Xenova/all-MiniLM-L6-v2`, https://huggingface.co/Xenova/all-MiniLM-L6-v2, Apache-2.0. Quantized q8 ONNX weights, approximately 23 MB with tokenizer/config. Semantic English feature extraction, normalized mean pooling, 384 dimensions. Not a generative model; cannot read photos/PDFs or validate physical stock.
- `@huggingface/transformers` 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), WASM CPU, four texts per batch, 256-token context. Finite normalized vector shape is checked before ranking. Similarity can mislink negation, unrelated notes or near-identical product variants. Every suggestion needs human verification.
- Approximately 50 MB first download: model/tokenizer ~23 MB from huggingface.co/hf.co and their CDN plus ~27 MB same-origin WASM. Bundled app, worker and module factory are locally hosted. Uses byte-identical immutable WASM from `../20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`; preserve that earlier build in combined deployment. SHA-256 recorded in asset audit.
- Modern module workers and WebAssembly SIMD required; CPU path does not require WebGPU. Several hundred MB available RAM recommended. Desktop Chrome tested; physical phones, low-memory devices and other browsers untested. No promise of universal phone performance.

## Privacy, caching and failures
No API key, backend, analytics or optional remote inference. User content remains in browser memory; model weights download without sending notes. No app-initiated user-data persistence; exported files are user initiated. Worker/runtime Cache API and Transformers.js model caches store public assets, not input. Cache eviction/private browsing can force redownload. First load requires internet. **Only fresh-worker offline inference within an already-open warmed page was tested**; offline reload/navigation is not supported or promised. Download progress, inference batch progress, cancellation and retry are exposed. Cancellation terminates workers; run identity protects delayed downloads, file reads and results. 180-second timeout, network/runtime/worker errors and malformed embeddings produce errors, never fabricated output. Browser caches may retain downloads after cancellation; user content is not cached by the app.

Limits: 2–8 catalog products; 1–24 count records; descriptions 400 characters, titles 80, IDs/bin names 40; originals ≤18,000 JSON characters, audit/file import ≤1 MB. Quantities/book counts/tolerance whole integers 0–1,000,000; unit cents 1–1,000,000. Single currency and unit per product, no fractional counts. These limits keep arithmetic within exact safe integers. Unsupported CSV/PDF/photo input is rejected. CSV quotes and formula-like text are escaped, signed numeric variance remains numeric. Structured schemas prevent lost records. Audit is a worksheet, not inventory/accounting certification.
