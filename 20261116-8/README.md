# Rank Mirror

For product leads and committee facilitators reconciling two complete priority lists. Local neural embeddings match paraphrased observations to a shared item dictionary; people verify identities, sides and ranks before a deterministic pairwise audit. This differs from ballot counting, vendor scoring and checklist revision: it diagnoses ordinal rank disagreement with explicit ties, without selecting a winner.

## Workflow

1. Load either wholly synthetic example or paste/import JSON. Supply context, a discussion `maxReversals` limit (0–28), 2–8 canonical `items` (`id`, `label`, `description`) and 1–24 `observations` (`id`, `description`, `list`: `A`/`B`, integer `rank`: 1–100). Smaller rank means higher priority. Repeated rank values intentionally express ties; gaps have no magnitude meaning.
2. Explicitly load AI; before this there are no model-host requests. Watch model file / four-text batch progress; Cancel terminates its worker. Network errors, missing WASM/module workers, malformed vectors and a 180-second timeout stop the run with no fake result. Retry explicitly.
3. Inspect the top two canonical descriptions and cosine scores (not confidence). Correct the item, list or rank, annotate and approve or hold every observation. Each change invalidates exports; semantic/rank edits reset approval. Undo restores the previous review; originals never change. Imported source text is model data, never tool authority.
4. Apply review. Each list must contain each canonical idea exactly once. Holds, duplicates and missing items block the entire comparison while remaining exportable in the audit. No silently dropped items.
5. Examine every unordered pair: concordant, reversed, tied only in A, tied only in B or tied in both. Compare reversal count with your limit. Kendall tau-b adjusts for ties; it is **undefined**, not zero, when either entire list is tied. The simple baseline counts shared items, ignoring ordering. Counts and ordinal association are descriptive, not measured business improvements or statistical significance.
6. Download current complete JSON audit, all-record CSV, pair CSV (ready only) or Markdown discussion worksheet; clipboard copies current Markdown. JSON audit reimport restores originals only, requiring fresh AI and review. CSV quotes commas/newlines/quotes and prefixes formula-like text with an apostrophe; numeric ranks remain numeric strings. JSON is lossless; CSV formula protection is intentional. There are no external actions, remote account access or invitations.

## Real AI, assets and privacy

- Model: [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0. Quantized q8 ONNX feature extraction, normalized mean pooling, 384 finite embedding dimensions. It performs semantic identity suggestions, not rank inference. Input ranks and list identities are supplied, then manually reviewed. Nearest-neighbor selection follows actual neural embeddings; no keyword/fake fallback.
- Runtime: Transformers.js 4.3.2 / ONNX Runtime WASM CPU, permissively licensed Apache-2.0 / MIT runtime dependencies. Immutable same-origin worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`; factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`; WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. **Preserve these older published builds.** Byte lengths and SHA-256 values are recorded in asset audits. Worker protocol: `{id,texts}` → progress/batch/result `{id,vectors}` or error. Four texts per inference batch. Inspected tokenizer ceiling 512 tokens; the pipeline's unused `max_length` option is not advertised as an enforced 256-token cap.
- First explicit run needs internet: approximately 23 MB model plus 27 MB CPU WASM and ~1 MB worker/runtime code; Hugging Face and its CDN host the model. The app and shared runtime assets come from GitHub Pages. No user descriptions, ranks or annotations leave the device, no API keys are requested and there is no optional provider integration. Tests assert GET-only traffic without request bodies and no fixture content in full request URLs; recorded reports remove signed CDN query values.
- Worker source and WASM factory/binary use Cache API; Transformers.js caches model files. Fresh-worker real inference was tested with all network disabled **inside an already-open, warmed page**. Offline startup, navigation and reload are not promised. Private mode, browser eviction or disabled caching may require downloads again. User sources and reviews are memory-only and disappear on reload unless exported. Model/runtime caches are separate from user data.
- Current desktop Chrome with WebAssembly SIMD, module workers, Cache API and several hundred MB available RAM is tested. WebGPU is not required. Physical phones, Safari/Firefox, assistive technologies and all hardware are unverified. The responsive UI was exercised at 1440, 390 and 320 px.

## Bounds and limitations

50,000 source characters; imported JSON/audit files under 2 MB; descriptions/context/labels ≤300 characters; review notes ≤1,000; IDs must match `[A-Za-z][\w-]{0,29}`. Up to 8 ideas and 24 observations (32 embedded texts) protect browser resources; a complete ready comparison uses two observations per idea. Run IDs protect late model results, worker fetches and file reads from overwriting newer inputs.

An embedding always returns a nearest candidate, even for unrelated text, negation or embedded instruction-like language. Human review is mandatory; semantic proximity is not identity or correctness. Two tiny fixtures are not universal accuracy evidence. Correct catalog scope and intentional ties before use. Tau-b = `(C−D)/sqrt((C+D+T_A)*(C+D+T_B))`, where one-sided ties enter their corresponding factors; both-sided ties are omitted. All pair counts sum to n(n−1)/2. No consensus, priority strength, p-value, causal comparison or decision authority is inferred. Held/incomplete lists do not produce partial statistics.
