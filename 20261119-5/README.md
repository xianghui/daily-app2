# Link Commons

A local-AI bandwidth planning worksheet for IT operators reconciling concurrent transfer requests. Neural route matching reduces manual interpretation of inconsistent transfer descriptions; mandatory human review feeds deterministic weighted max-min allocation across overlapping fixed paths. No network configuration, file transfer or traffic measurement is performed.

## Workflow and formats
1. Choose a synthetic example or paste/import source JSON. Supply `context`; 1–8 `links` with unique `id`, `label`, positive `capacity` in Mbps; 2–8 route `items` with unique `id`, `label`, `description`, and a nonempty list of unique known `links`; 1–24 transfer `observations` with unique `id`, `description`, positive `demand` Mbps and priority `weight`.
2. Edit goals/constraints in source JSON: capacities, fixed paths, demands and relative positive weights. Link capacity and demand range 0.001–1,000,000; weights 0.1–100. Text fields 1–300 characters; complete source ≤50,000 characters. Import `.json` under 2 MB. Imported instructions are inert text, never authority to upload content or obtain credentials.
3. Explicitly load AI. Inspect each route and top-two source descriptions with cosine similarity (NOT confidence). Correct route, demand or weight; these edits reset approval. Approve each transfer or hold the entire worksheet. Notes support multiline text; undo restores the prior review. Originals remain unchanged.
4. Apply reviewed plan. Pending reviews fail validation; any hold produces a blocked audit without fabricated allocations. Every source request survives, including holds. Each flow consumes its planned rate on every link in its fixed path.
5. Export actual current JSON, CSV or Markdown, or copy the Markdown worksheet. Every review edit invalidates the applied snapshot and disables exports until reapplied. JSON contains lossless original input, reviews, evidence, allocations, link loads and filling trace. CSV contains every original/current reviewed transfer and rates; potentially formula-like string cells are apostrophe-prefixed, numeric fields stay numeric. Markdown contains rates, capacities, source register and an actionable verification checklist. Reimporting an audit restores **originals only** and requires fresh inference/approval; it does not trust saved approvals.

## Real AI and static runtime
[Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, quantized q8 ONNX. [Transformers.js](https://github.com/huggingface/transformers.js) 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), CPU/WASM, one thread. Real inference produces normalized mean-pooled 384-dimensional embeddings. Cosine ranks route descriptions against transfer notes, enabling paraphrase matching rather than literal-label lookup. AI does not infer demand, paths, capacity, priority, permissions or transfer completion. Nearest-route retrieval can mislink negation or unrelated text. No model-produced numeric confidence is shown.

Four texts per inference chunk, at most 32 texts. The shared worker passes `max_length:256`, but this pipeline does not enforce that argument: actual tokenizer model ceiling is 512 tokens. The app independently bounds each text to 300 characters. Vector count, finite components, dimension and normalization are validated before recommendations.

To avoid duplicating runtime bytes near the collection size limit, this app uses these immutable same-origin production assets; preserve their originating apps:
- `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js` (embedded Transformers.js/ONNX worker, text/vector protocol `{id,texts}` → progress, batches, `{id,type:'result',vectors}`)
- `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`
- `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`

The app code and all runtime dependencies are hosted in the collection, not a third-party JS CDN. The model's default host revision follows the model repository; no reproducibility claim across future upstream changes. Model weights/tokenizer/config download from Hugging Face and its CDN only after explicit loading. Budget approximately **23 MB model plus 27 MB WASM**, plus worker and tokenizer files; internet is required initially. Progress, cancel/retry and 180-second timeout are visible. No WebGPU needed. WebAssembly SIMD, module workers, Cache API, and several hundred MB available RAM are required. Tested desktop Chrome with GPU disabled; physical phones, other engines and minimum RAM limits are unverified. Unsupported runtime/download failures give actionable errors, never fake AI or a hidden remote fallback.

## Privacy and offline scope
No key, account, API provider integration or remote inference. User text stays in browser memory and is posted only to the local worker. Outbound requests download static assets/weights; source text is not uploaded. No input/history localStorage persistence. Runtime/model caches contain downloaded assets, not user documents. Worker source is stored in `link-commons-worker-v1`, runtime factory/WASM in the shared runtime cache, model files through Transformers.js Cache API. Cache availability is best effort; eviction requires downloading again. Browser exports are explicit local downloads.

After a successful online run, **fresh-worker inference in the same already-open warmed page** is tested with the browser offline. Offline reload/navigation, first use without internet, private-mode persistence and cache-evicted processing are not promised. Cancellation terminates the worker and increments run identity; stale messages and delayed file reads cannot overwrite newer input/results.

## Deterministic math and comparison
Weighted max-min progressive filling starts all flows at zero. Each active flow rises at its positive weight times a common increment. The next increment is the minimum of each residual demand divided by weight and each residual link capacity divided by summed active weights using that link. Demand-satisfied flows or flows crossing a saturated link freeze. Continue until all flows freeze (at most one step per flow). Link capacity and demand bounds are verified; all source identities are conserved. Doubles are used, with bounded numerical tolerances and display rounding; JSON retains numeric precision.

Baseline: each flow receives the minimum, over its links, of `link capacity × its weight / total weight of all flows using that link`, capped at demand. It does not redistribute unused shares. Both methods respect capacities. The UI computes sum allocated flow rates, baseline sum, each link load/spare and the filling trace from current reviews. Sum of flow rates is **not** sum of link loads. Displayed rates are planning estimates, not measurements or claimed speed gains. Weighted max-min fairness is not maximum aggregate throughput, route optimization or a latency guarantee. Fixed paths, steady concurrent demands and fluid sharing only: no overhead, packet loss, TCP behavior, bursts, time evolution or measurement.
