# State Orchard

A local-first routing-table workroom for support playbook designers. Rough handoff endpoint notes are tedious to reconcile, and equal current messages do not imply equal future behavior. Real neural identity matching assists the first problem; exact deterministic Moore-machine reduction solves the second only after human review.

## Workflow

1. Start with **Support twins** or **Library ladder** (synthetic only), paste JSON, or import source/audit `.json` up to 4 MB. Set the start state, explicit visible outcomes and event labels. Provide exactly one transition per state/event slot. The source editor is the editable constraint/catalog surface.
2. Read the download/privacy notice, then explicitly **Load AI & reconcile**. Four texts are embedded per chunk. Download progress and inference text counts are shown; cancel terminates the worker. Retry never silently substitutes heuristic or canned output.
3. Review every source-linked from/to suggestion, event and visible outcome. Evidence is ranked cosine similarity, **not confidence**. Correct identities, approve each row or hold uncertainty. Endpoint/event changes reset approval. Undo restores the last review edit; source/review changes invalidate the applied snapshot and exports.
4. Apply the reviewed scenario. Holds withhold the entire reduction. Duplicate/missing state/event slots block it. Reachability removes unreachable states from the reduced machine but retains them in the original audit. Partition refinement groups states only when their visible outputs and all future event behavior agree. Output/transition invariants prove equivalence; product-graph breadth-first searches provide shortest distinguishing sequences between every pair of reduced states, certifying minimality for this table.
5. Inspect the original catalog count, reachable count, minimal count and consolidated reachable count. These are actual table counts, not claimed time savings or neural accuracy. The fixtures yield 4→2 reachable states and 3→3 reachable states (one unreachable catalog state), respectively.
6. Download current reviewed **JSON** (lossless originals/reviews/analysis), complete audit **CSV**, distinguishing-test **Plan CSV**, **Markdown** audit, or reduced-machine **DOT**. Copy includes the current worksheet and complete audit. CSV formula-like text is prefixed with an apostrophe; JSON retains exact strings. Reimport audit JSON restores originals only, requiring fresh inference and renewed review. No external workflow is executed or changed.

## Real AI and static runtime

- Model: [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), quantized q8 ONNX, Apache-2.0. Mean-pooled normalized 384-dimensional embeddings rank endpoint notes against supplied state descriptions. Neural inference handles paraphrases that literal IDs cannot match; it does **not** determine equivalence, infer transitions/events/outcomes, or prove identity.
- Transformers.js **4.3.2**, Apache-2.0; ONNX Runtime Web, MIT. Shared immutable worker: `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`; factory: `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`; CPU WASM: `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve those published apps/assets. Hashes are in `runtime-dependency-audit.json` and are checked locally and publicly.
- First use needs internet: approximately **23 MB weights plus 27 MB WASM**, tokenizer/config, ~0.55 MB worker and ~0.05 MB factory. Runtime is same-origin; public weights download from Hugging Face and its CDN. No request to a model host before explicit loading. No key, paid service, remote inference, provider integration or agent credentials.
- Single-thread WASM/CPU is the tested default, not a WebGPU dependency. Requires secure context, module workers, WebAssembly SIMD, Cache API for offline reuse, and several hundred MB available RAM. Desktop Chrome headless with GPU disabled tested. Physical phones, Safari/Firefox and low-memory devices are **untested**; phone-width layout tests are not physical-device inference tests.
- Worker source, factory, binary and model assets cache locally when supported. Cache eviction/private mode may force a new internet download. **Tested offline scope: fresh-worker inference in an already-open warmed page with all network disabled. Cold offline navigation/reload is not promised**; no app-shell service worker.
- Model URLs track upstream `main`; metadata fingerprints are recorded, not a pinned future-availability guarantee. Cache is browser-managed; clearing site data removes cached assets.

## Privacy, schemas and limits

All user text stays in React memory and the local worker. Network requests are public file GET downloads only; no document upload. Model download is distinct from content upload. No analytics, API keys, content persistence, database connections, sending or deletion. Audit exports may contain sensitive originals; keep your own downloaded files appropriately private. All committed fixtures are synthetic.

Source JSON fields: `title`, `start`, `states: [{id,description,outcome}]`, `events: [string]`, `transitions: [{id,fromNote,event,toNote}]`. Bounds: 2–8 states, 1–4 events, 2–32 transitions equal to states×events, source ≤60,000 characters, imported envelope ≤4 MB, IDs/events ≤50 characters, descriptions/notes ≤200, outcomes ≤100, reviewer notes ≤2,000. Every vector must be finite, normalized and exactly 384 values; count must equal submitted texts. Four-text chunks, actual tokenizer model maximum **512 tokens** (the worker's requested `max_length:256` does not override the feature-extraction tokenizer limit). Text bounds keep samples short.

Inputs are data, never instructions to request credentials or change authority. Unknown/negated/near-synonym notes still select a nearest neighbor; there is no safe automatic identity threshold. Human holds are necessary. A 180-second watchdog, run identities and worker termination protect against stale responses, network failures, malformed vectors/envelopes, cancellation and unavailable runtime. File reads and worker fetches are identity-guarded too.

## Behavioral assumptions and limitations

Only **total deterministic Moore machines** with outcome observations on states are supported. Every event is defined from every state. Equality is exact outcome-string equality. Put every observable distinction into that output contract: timing, entry/exit side effects, hidden variables, conditional guards, probabilities, history and concurrent behavior are not modeled. Do not use this worksheet to justify merging real systems with unmodeled effects. No actions or real system changes occur. Repeated outcome text alone is insufficient; future transitions matter. Unreachable states are retained in the audit, not in the minimal reachable machine. The supplied start state determines reachability. Source descriptions and human-friendly IDs are identity hints, not extra preserved outputs.
