# Causal Lantern

A local-first **distributed incident log review** worksheet. Incident reviewers often paste interleaved event notes whose service names differ and whose source order is mistaken for global chronology. Real neural service reconciliation reduces manual identity lookup; mandatory human review precedes exact logical-clock analysis. No log server connection, content uploads, incident actions or clock synchronization.

## Workflow
1. Choose **Checkout incident** or **Editorial round trip**, or import/paste JSON. Supply 2–8 services (`id`, `description`) and 2–32 events (`id`, `serviceNote`, `seq`, `kind`, `message`). Sequences are positive integers 1–10,000, local to a service, not wall timestamps. `kind` is `local`, `send` or `receive`; local messages must be empty. Send and receive events need an exact correlation ID. Edit source to set the catalog and constraints.
2. Explicitly click **Load AI & reconcile**. First use needs internet: approximately 23 MB q8 model weights plus 27 MB WASM and smaller JS/tokenizer/config files. Progress shows downloads and chunks. Cancel terminates the worker; retry starts a new run.
3. Inspect each source note and cosine-ranked service evidence. Verify/edit service, sequence, event kind and message ID; approve or hold each event. Metadata edits reset approval. Multiline reviewer notes and undo are available. Original inputs are never overwritten by reviews.
4. **Apply reviewed scenario**. A hold withholds the whole worksheet while retaining the complete audit. Every message must have exactly one send and one receive on different services. Duplicate local sequence positions and contradictory causal cycles block output. Local-order plus send→receive edges produce vector clocks, all unordered event pairs, shortest directed witnesses and one possible topological linearization. That linearization is NOT measured wall chronology.
5. Download lossless JSON, complete event CSV, pair-witness CSV or Markdown with full audit; copy the worksheet. Every edit invalidates exports. Audit JSON reimport restores originals only and requires renewed inference/review. No external actions.

The **source-order baseline** asserts that the left event precedes the right event for every pair in original pasted order. The worksheet counts reversed causal pairs and concurrent pairs for which that assertion lacks supplied evidence. This is a computed diagnostic, not measured productivity, AI accuracy or a speedup claim. Concurrent means neither directed path exists in the supplied graph, NOT simultaneity. Missing events/dependencies can make real relations appear concurrent.

## Real AI / model / licenses / runtime
- [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, q8 ONNX, about 23 MB. Real normalized mean-pooled 384-value embeddings compare every event service note to the catalog descriptions. No hard-coded responses, generic chat, generation or instruction execution. Model only suggests identity; it does not infer message IDs, local order or missing links.
- Transformers.js 4.3.2 (Apache-2.0); ONNX Runtime Web (MIT). Single-thread WASM CPU SIMD, no WebGPU or API key. Tested real inference with GPU disabled in desktop Chrome.
- Same-origin immutable shared worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`, runtime factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`, and WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve the originating apps and assets. SHA-256/size audits are in `runtime-dependency-audit.json`. Sharing avoids duplicating ~27 MB in the nearly full collection.
- Four texts per chunk. Tokenizer context is 512 tokens; the feature-extraction pipeline ignores the passed `max_length:256` option. Notes/descriptions ≤200 characters bound individual texts but unusual tokenization may still truncate. Model revision is not pinned; upstream changes can affect matching.
- Finite normalized vectors of exact expected count and 384 dimensions are required before suggestions. Cosine similarity is not confidence or proof of identity. Unknown/negated descriptions may match a wrong nearest service; hold uncertainty.

## Privacy, download and offline scope
Before explicit loading there is no model-host request. Afterwards only public model/runtime assets download from this site and Hugging Face/CDN. User content is passed into a local worker, never to a provider. No credentials, optional remote provider, telemetry or real production logs. Inputs/reviews/results live only in page memory. Browser Cache API stores runtime/model assets, not input metadata. Cache eviction, private mode or unavailable cache storage may require internet again.

Requires HTTPS/localhost, module workers, WebAssembly SIMD and several hundred MB available RAM. Desktop Chrome is tested with GPU disabled; viewport widths 1440, 390 and 320 tested. Physical phones, low-memory hardware, Safari and Firefox are untested. Offline claim is deliberately limited to **fresh-worker inference in an already-open warmed page with networking disabled**; cold offline navigation/reload is not promised. Cancellation, run IDs, guarded file reads/worker fetches and a 180-second timeout prevent stale output and fabricated fallback results.

## Formats, bounds and deterministic guarantees
Source JSON ≤60,000 characters; `.json` files ≤4 MB accommodate audit envelopes. Unique service/event IDs and message IDs ≤50; title/notes/descriptions ≤200; reviewer notes ≤2,000. Exact sequence integers 1–10,000, unique per reviewed service. Sequence gaps are permitted but no missing event is invented. Local edges connect successive observed events; message IDs must pair exactly. Broadcast/retries need separate IDs and explicit events. No unbounded graph search: at most 32 nodes, 8 clock components and 496 pairs.

Deterministic topological propagation merges predecessor clocks and increments the event's service component. Independent reachability and vector-clock comparisons must agree for every pair. Every directed witness uses actual supplied edges. All event IDs survive, held audits retain originals, every pair appears once, and each reported baseline count is derived from current reviews. This is a worksheet, not proof that logs are complete or that service assignments are correct.

JSON is lossless. CSV quotes commas, quotes and multiline cells; formula-like string cells beginning `= + - @ tab CR` get an apostrophe guard. Pair CSV includes the original left/right source order, logical relation, shortest witness and baseline label. Markdown includes complete JSON. Downloads reflect applied current reviews, never stale defaults.

## Validation and known limitations
Observed real model results on the two small synthetic fixtures: 12/12 simple service labels; checkout 11 ordered/4 concurrent pairs and 5 source-order inversions; editorial 14 ordered/1 concurrent pair and 9 inversions. This is not a general accuracy estimate. An unknown/negated prompt still received a nearest-service suggestion and stayed pending; no instruction was executed. Human review is essential.

Independent Floyd–Warshall closure checks on 160 randomized traces validated pair relations and witnesses. Browser checks cover maximum batches, conservation, reviews/edits/holds/undo, downloaded artifact parsing and reimport, clipboard, input limits, cancellation/retry, offline fresh-worker inference, network/download failure, unsupported runtime, malformed output, timeouts, delayed file/worker/error races and narrow layout. See `VALIDATION.md` and machine-readable reports for observed local, assembled and public outcomes.

Limitations: partial metadata only; no actual log collection, missing-event discovery, retransmission deduplication, broadcast expansion, physical time, duration estimates, fault attribution, alerting or incident actions. Sequence gaps and missing service-local logs can hide dependencies. A total order is not inferred where evidence only establishes a partial order.
