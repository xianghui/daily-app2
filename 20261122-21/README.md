# Filter Budget

A local-first Bloom-filter **memory sizing worksheet** for data engineers. Rough workload aliases slow repeated inventory reviews; real MiniLM embeddings reconcile descriptions against a supplied catalog before mandatory human approval. A bounded dynamic program then allocates a fixed memory budget to minimize **estimated unnecessary backend milliseconds**. No actual filter is constructed, no service is contacted and no configuration changes occur.

## Workflow
1. Choose Commerce lookups or Library indexes, or paste/import JSON. `title` ≤200, `budgetKiB` integer from filter count to 64. Supply 2–8 `filters` with unique `id` ≤50, `description` ≤200 and integer `lookupMs` 1–10,000. Supply 2–32 `batches` with unique `id` ≤50, `filterNote` ≤200, `distinct` 1–1,000,000 and `absentQueries` 0–10,000,000. Source ≤60,000 characters; source/audit `.json` imports ≤4 MB.
2. Set the budget, catalog and backend-cost assumptions in the source editor. Explicitly click **Load AI & reconcile**. Internet is needed initially: ≈23 MB q8 weights plus ≈27 MB WASM and smaller JS/tokenizer/config assets. Loading/chunk progress and cancellation are visible.
3. Inspect every original note and cosine-ranked evidence; edit filter identity/counts, add multiline reviewer notes, approve or hold. Counts/identity edits reset approval. Undo restores the last review. Originals remain unchanged.
4. **Apply reviewed scenario**. Pending reviews block output. Any hold withholds the entire allocation but allows a complete audit export. Distinct-key batches linked to a filter MUST be disjoint; deduplicate upstream if they overlap. Truly absent queries are required, not total traffic. Missing facts are never inferred by AI.
5. Compare equal-memory and optimized plans. Download lossless JSON, batch audit CSV, plan CSV or complete Markdown; copy the worksheet. Every input/review edit invalidates exports. Audit reimport restores originals only and requires renewed inference/review. No deployment, backend access or other external action.

## Real model/runtime and privacy
- [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, q8 ONNX ≈23 MB. Real normalized mean-pooled 384-value embeddings match batch descriptions to catalog descriptions; no canned response or deterministic fake-AI fallback. It does not generate counts, costs, instructions or confidence.
- Transformers.js 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), single-thread WASM CPU SIMD. No WebGPU, API key, paid service, telemetry or optional remote provider. Requires HTTPS/localhost, module workers, WASM SIMD and several hundred MB RAM. Tested in desktop Chrome with GPU disabled; physical phones, low-memory devices, Safari and Firefox untested.
- Immutable same-origin shared worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`, factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`, WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve originating builds. Sizes/hashes: `runtime-dependency-audit.json`.
- Four texts per chunk; 40 maximum texts. Worker feature-extraction pipeline tokenizes with truncation at tokenizer model_max_length 512; its supplied max_length 256 option is ignored by the pipeline. Individual descriptions ≤200 characters bound practical context; unusual tokens can truncate. Model main revision is unpinned: upstream changes may affect matches.
- Exact vector count, dimension, finite values and normalization validated. Unknown/negated notes still get nearest-neighbor suggestions, not authoritative identities; human hold is essential. Imported text is data, never tool instructions.

No content leaves the browser default path. After explicit loading only public model/runtime downloads from this site and Hugging Face/CDN occur. Content goes to a local worker; no content in URLs or request bodies. Inputs and reviews stay in page memory. Cache API stores runtime/model assets, not source metadata. Eviction/private mode can require internet again. Offline scope actually tested: **fresh-worker inference in an already-open warmed page with network disabled**. Cold offline app navigation/reload is not promised. Run IDs, worker termination, guarded asynchronous file/fetch completion and 180-second timeout reject stale/cancelled output. Network/runtime failures show errors, not synthetic matches.

## Deterministic sizing model
For each filter aggregate reviewed disjoint keys n and absent queries q. For every allocation b in whole KiB blocks and every integer hash count k=1…12 compute p=(1−exp(−kn/(8192b)))^k; expected backend work = q×p×lookupMs. Select the best k for each b, then dynamic-program all filter/block choices with one-block minimum and exactly the total budget. Empty catalog filters still receive one block. Tie outcomes are deterministic but not unique. The baseline splits the same blocks equally, assigns remainder to catalog order and independently chooses its best 1–12 hash count. Both totals, not invented improvements, are shown.

This is the standard independent uniform hashing approximation, **not measured false-positive behavior, a latency forecast, accuracy or a guarantee**. Assumes append-only sets, no overlapping distinct-key batches, truly absent query counts and fixed backend work per miss. It excludes hash CPU/energy, positive lookups, cache effects, adversarial inputs, deletions, growth, counting filters, correlations and hardware configuration limits. Optimizing weighted milliseconds need not minimize false-lookup count. These tiny sizing budgets are educational/pilot worksheet bounds, not universal production recommendations.

Memory and both workload totals are conserved. JSON retains all records, originals and reviews including holds. Audit CSV quotes commas/quotes/newlines and prefixes formula-like string cells starting = + - @ tab CR with an apostrophe; numeric values stay numeric. Plan CSV exports exact bytes/hash counts, estimates and source batch IDs. Markdown includes complete JSON. Exports reflect current applied reviews only.

## Validation
See `VALIDATION.md` and machine-readable reports. Two materially different fixtures ran real inference: 6/6 simple expected identities, not general accuracy. Independent exhaustive allocation enumeration checked 90 randomized small cases. Maximum 8-filter/32-batch inference, fresh-worker offline execution, malformed model/runtime/network/timeout handling, cancellation/retry, stale races, review/hold/undo, multiline/formula-safe artifacts, clipboard, round-trip reimport and desktop/320/390 layouts were checked. Physical devices and cold offline reload remain untested.
