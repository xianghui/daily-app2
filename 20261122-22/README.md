# Grammar Harbor

A local-first review desk for maintainers of small command/configuration **token grammars**. Informal production references often use inconsistent names; real neural embeddings reconcile them against a supplied nonterminal catalog before mandatory human review. Exact grammar analysis then exposes LL(1) lookahead collisions that a first-literal-token scan misses. No parser is executed, no code generated, no accounts changed.

## Workflow and formats
1. Choose **Command language** or **Menu conflict**, or paste/import JSON. Set `title` (≤200), exact catalog `start` ID and 2–8 `nonterminals` with unique `id` (≤50) and natural-language `description` (≤200).
2. Supply 2–24 `rules` with unique `id` (≤50), informal `lhs` note (≤200) and `rhs` array (0–8 symbols). Each symbol is exactly `{terminal:"literal token"}` (≤50) or `{ref:"informal nonterminal note"}` (≤200). Empty rhs means epsilon; `$` is reserved for end-of-input. Tokens are exact strings, not regular expressions. Source ≤60,000 characters; source/audit .json imports ≤4 MB. Unsupported formats fail visibly.
3. Click **Load AI & reconcile** to download model/runtime and run real MiniLM inference. Review every lhs/rhs reference, inspect cosine evidence (not confidence), edit identity, add multiline notes (≤2,000), approve or hold. Identity edits reset approval; undo restores the last review. Correct tokens/structure in source JSON and rerun. Original inputs never mutate.
4. **Apply reviewed scenario**. Pending reviews block output; any hold withholds the whole analysis but preserves complete audit exports. Inspect nullable, FIRST, FOLLOW and prediction sets, productive/reachable/undefined flags, all table conflicts and exact source rule IDs. Zero collisions alone does not certify a useful or secure parser.
5. Download JSON (all originals, reviews, evidence, sets/table), reference audit CSV, table CSV (all filled cells and every alternative), or Markdown (worksheet plus complete JSON). Copy the current worksheet/audit. Input/review edits invalidate exports. JSON audit reimport restores originals only and requires fresh inference/review. CSV strings are quoted and formula-like initial = + - @ tab CR are apostrophe-prefixed; original exact strings remain in JSON. Empty/unlisted parse-table cells denote errors, not epsilon rules.

## Real AI, downloads and privacy
- [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, q8 ONNX ≈23 MB; normalized mean-pooled 384-value neural embeddings link description/reference paraphrases. AI does not invent productions, infer terminal strings, repair grammars, request credentials or execute instructions. Unknown/negated/technical symbols still get a nearest candidate: verify or hold.
- Transformers.js 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), single-thread WASM CPU SIMD. No WebGPU requirement, API key, paid service, telemetry or optional remote provider. Requires HTTPS/localhost, module workers, WASM SIMD and several hundred MB RAM. Tested desktop Chrome with GPU disabled; physical phones, low-memory devices and other browsers untested.
- Shared immutable same-origin worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`, factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs` and WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve originating builds. Runtime and worker bytes are audited in `runtime-dependency-audit.json`.
- Four texts per chunk, maximum 224 texts/56 chunks. Worker pipeline truncates at tokenizer model_max_length 512; its supplied max_length 256 option is ignored by Transformers.js feature extraction. Descriptions ≤200 characters limit practical context; unusual tokens may truncate. Validate exact vector count/dimension, finite values and unit normalization. Upstream model main revision is unpinned and can change outputs.
- First use needs internet from this site and Hugging Face/CDN; ≈23 MB model + ≈27 MB WASM plus JS/factory/tokenizer/config files. Explicit loading, progress, cancellation and 180-second timeout. User grammar goes to a local worker only, not URLs/request bodies. No real/private fixtures or credentials included. Inputs/reviews stay in page memory; Cache API stores public runtime/model assets, not user data. Imported strings are data, never tool authority.
- Offline scope tested: **fresh-worker inference in an already-open warmed page with network disabled**. Cold offline navigation/reload is not promised. Private mode/cache eviction requires internet again. Errors never substitute canned inference. Run IDs, terminated workers and guarded async file/source reads prevent stale/cancelled output from replacing a newer input.

## Deterministic checks and limitations
Nullable is a least fixed point over productions with all-nullable nonterminal rhs (including empty rhs). FIRST propagates through nullable prefixes. FOLLOW starts with `$` on the exact start symbol and propagates suffix FIRST and enclosing FOLLOW at nullable suffixes. A production predicts FIRST(rhs), plus FOLLOW(lhs) when nullable. The LL(1) table retains all production IDs for each `(nonterminal, lookahead)`; a cell with >1 production is a conflict. Separate fixed points flag terminal-generating productivity and reachability from start. Every original production is retained even if unused.

The baseline counts duplicate `(lhs, first literal terminal)` cells **only when the first rhs symbol is a terminal**. Full analysis also captures indirect/nullable starts. Both counts are computed, not accuracy or time savings. The menu fixture has a nullable beverage prefix before `meal`: baseline misses the `order/meal` collision; full table retains M1/M2. No automatic choice or grammar rewrite occurs.

This accepts BNF-like typed token sequences only: no regex lexer, EBNF, precedence, semantic predicates, general ambiguity proof, left-recursion rewrite, generated parser or source-code execution. LL(1) collision means unsuitable for this one-token predictive table, not proof of language ambiguity. Nonproductive/unreachable rules need review even with no collisions. Symbols with no productions remain explicitly flagged; no missing rule is fabricated. Tokens and nonterminal IDs occupy separate typed namespaces.
