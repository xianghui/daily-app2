# Lock Orchard

A local-first review desk for maintainers auditing recurring mutex-acquisition notes. Rough names often refer to the same lock; real neural embeddings propose catalog identities before mandatory review. Exact graph analysis exposes multi-lock ordering cycles missed by pairwise reversal checks. No source code or process is accessed or executed.

## Workflow and formats
1. Choose **Consistent accounts** or **Three-way cycle**, or paste/import source JSON. Supply `title` ≤200 characters; 2–8 `locks` with unique `id` ≤50 and `description` ≤200; 2–24 `traces` with unique `id` ≤50 and an ordered `acquire` array of 1–8 informal notes ≤200 each. Every acquisition denotes an exclusive, non-reentrant mutex held until trace end. These assumptions are required, not inferred by AI.
2. Source text ≤60,000 characters; source/audit JSON imports ≤4 MB. Unsupported fields/formats, invalid structure and oversize data fail visibly; no extra metadata is silently discarded. Only supplied catalog identities can be selected.
3. Click **Load AI & reconcile** for real local MiniLM inference. Inspect the source trace/position, original note, proposed mutex and all cosine similarities (not confidence). Correct identity or source order, add multiline review notes ≤2,000, and approve or hold every acquisition. Identity edits reset approval. Undo restores the last review edit. Source edits require fresh inference/reviews.
4. **Apply reviewed scenario**. Pending references block output; any hold withholds the whole graph audit while retaining complete audit exports. Repeated mutex identities within a trace are blocked rather than silently interpreted as recursion. Review graph edges, shortest directed cycle with source witnesses, or one compatible ordering when acyclic. A compatible order is not an automatic code-change recommendation.
5. Download JSON (every original, review, similarity and graph result), acquisition audit CSV, edge-witness CSV or Markdown (worksheet plus complete JSON). Copy current worksheet/audit. Any review/input edit invalidates exports. Audit JSON reimport restores originals only; renew inference/review. CSV quotes all cells and apostrophe-prefixes string cells starting with = + - @ tab CR, including multiline formula-like strings. Exact strings remain in JSON.

## Real AI, privacy and requirements

The model materially links description/reference paraphrases; it does not infer ownership, lock lifetime, source behavior or safe reorderings. Unknown/negated/technical notes still select a nearest candidate: verify or hold. Imported instructions remain data, never authority or credential requests.
- Transformers.js 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), single-thread WASM CPU SIMD. No GPU or WebGPU needed; no API key, remote inference provider, paid service, telemetry or uploads. HTTPS/localhost, module workers, WebAssembly SIMD and several hundred MB RAM required. Desktop Chrome with GPU disabled tested; physical phones, low-memory devices and other browsers untested.
- Shared immutable worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`, module factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`, WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve originating builds/paths. Hashes in `runtime-dependency-audit.json`.
- Four texts per inference chunk; maximum 200 texts/50 chunks (8 catalog descriptions + 192 acquisitions). Pipeline tokenizer model_max_length is 512 tokens. Its max_length 256 option is ignored by this feature-extraction implementation; descriptions ≤200 characters bound practical context but unusual tokens may truncate. Validate exact vector count, 384 dimensions, finite numbers and unit normalization. Model main revision is unpinned and may change.
- Explicit first loading needs internet for this site and Hugging Face/CDN file downloads: ≈23 MB model + ≈27 MB CPU runtime, plus tokenizer/config/JS files. UI exposes size, loading status, batch progress, cancel and 180-second timeout. Only public file downloads; user notes go to a local worker, never request URLs/bodies. No credentials or real/private fixtures are included. Data/reviews remain in page memory, not persistent storage. Cache API stores public runtime/model assets only.
- Offline scope tested: **fresh-worker inference in an already-open warmed page with network disabled**. Cold offline navigation/reload is not promised. Cache eviction/private mode may require internet. Errors never substitute deterministic/canned AI. Run IDs, worker termination and guarded async file/worker reads prevent old results replacing newer input.

## Exact analysis and limitations
For every reviewed trace, add a directed edge from each earlier acquisition to every later acquisition, because earlier mutexes are assumed still held. Deduplicate edges but retain every trace/position witness. The baseline checks only opposite edge pairs (A→B and B→A). Breadth-first path searches from each vertex find a shortest directed cycle, including three-or-more-lock cycles missed by that baseline. If acyclic, Kahn topological ordering covers all catalog locks and satisfies every supplied edge. Unused catalog locks remain in that ordering. All traces and acquisition records survive exports.

Counts are computed, not measured time savings or confidence. A cycle is **potential order inversion, not proof of a reachable runtime deadlock**: mutually exclusive paths or higher-level serialization may make it unrealizable. Acyclic notes do not prove application safety or completeness. No mid-trace releases, shared/read-write modes, recursive locks, try-locks/timeouts, condition variables, callbacks or dynamic lock sets are modeled. Review such code manually and do not enter it as though it met these assumptions. No automatic reordering, code generation, live process inspection or system changes.
