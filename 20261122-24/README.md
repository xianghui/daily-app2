# Prefix Harbor

A local-first IPv4 forwarding review desk for maintainers reconciling recurring network change notes. Real neural inference maps informal next-hop descriptions to a supplied gateway catalog. Mandatory human identity review feeds exact longest-prefix/metric lookup, whole-address-space route shadowing and expected-destination checks. Nothing contacts or configures a router.

## Workflow, constraints and formats
1. Choose **Office exceptions** or **Shadowed warehouse**, or paste/import source JSON. Only `title` (≤200 characters), `gateways` (2–8 unique `id` ≤50 and `description` ≤200), `routes` (1–32 unique `id` ≤50, canonical IPv4 `cidr`, integer `metric` 0–65535, informal `nextHop` ≤200) and `probes` (1–32 unique `id` ≤50, dotted IPv4 `ip`, exact `expected` gateway ID) are accepted. Unknown source fields and noncanonical networks are rejected, not silently normalized. IDs are arbitrary bounded text, not commands. Leading-zero octets and IPv6 are unsupported.
2. Edit routes/metrics and probe expectations to set constraints/goals. Source ≤60,000 characters; source/audit `.json` imports ≤4 MB. Oversized, empty, malformed or unsupported inputs fail visibly. No personal fixtures are included.
3. Click **Load AI & reconcile**. Initial loading requires internet and may take time. Review every source route, original next-hop note, gateway proposal and cosine evidence (not confidence). Correct identities; add multiline notes ≤2,000; approve or hold. Identity edits reset approval; undo restores the previous review state. No auto-approval.
4. **Apply reviewed scenario**. Pending reviews block output. A hold withholds the whole routing audit but preserves all originals/reviews for export. Results compare supplied probe mismatches under first-match versus longest-prefix/lowest-metric forwarding, report exact per-route winning/ambiguous address counts and fully shadowed routes, and partition all IPv4 addresses including uncovered ranges. No route is removed.
5. Download complete JSON, route audit CSV, address Segments CSV or Markdown worksheet with complete audit; copy worksheet/audit. Exports always use the current applied review and are invalidated by edits. Reimport JSON restores originals only and requires renewed inference/review. CSV quotes cells and apostrophe-guards strings beginning with = + - @ tab or CR, including multiline formula-like strings. JSON preserves exact strings. Segments CSV winning-route IDs are JSON arrays, not ambiguous delimiter lists.

## Real AI, model and data flow
- [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, q8 ONNX ≈23 MB; real mean-pooled, normalized 384-dimensional neural embeddings on WASM CPU. This materially reconciles semantic paraphrases, not only literal names. Similarity does **not** prove gateway identity. Unknown, negated or technical notes still choose a nearest candidate: correct or hold them.
- Transformers.js 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT). The shared immutable same-origin worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js` bundles the browser inference library. Module factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`; WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve originating builds and URLs. Hashes in `runtime-dependency-audit.json`. Reusing these already-published assets keeps the collection within its existing size guard.
- No API key, mandatory paid service, remote inference integration, telemetry or content uploads. Inputs/reviews stay in page memory; text goes only to a local worker. Only public site/runtime and Hugging Face/CDN model files download. Imported instructions remain data and cannot request credentials, tools or external actions.
- Four texts per chunk; at most 40 texts/10 chunks. Validate count, 384 dimensions, finite numbers and unit normalization before ranking. Shared pipeline tokenizer context is 512 tokens. Its `max_length:256` option is ignored by feature-extraction implementation; descriptions/notes ≤200 characters bound practical context, but unusual tokenization can truncate. Model revision `main` is unpinned and can change.
- First load ≈23 MB model + 27 MB WASM runtime plus tokenizer/config/JS. HTTPS/localhost, module workers, WebAssembly SIMD and several hundred MB RAM required. Single-thread CPU works without WebGPU; desktop Chrome with GPU disabled was tested. Physical phones, low-memory devices and other browsers are untested. Download/file/batch status, cancellation and 180-second timeout shown. Model/network/runtime errors never switch to canned or deterministic AI suggestions.
- Cache API stores only public worker/runtime/model assets. Tested offline scope: a fresh worker can infer in an **already-open warmed page** with network disabled. Cold offline navigation/reload is not promised; eviction/private mode can require internet again. Async file reads and worker fetches use run IDs; cancellation terminates workers; stale responses cannot replace current input/results.

## Exact deterministic audit and limitations
Each canonical CIDR becomes an inclusive integer interval. All route boundaries, zero and 2^32 create disjoint contiguous elementary segments. Matching routes are ranked by longest prefix, then lowest metric. Equal-rank same-gateway duplicates share winning coverage and retain every route ID; equal-rank different gateways are explicitly ambiguous, never arbitrarily selected. Adjacent segments need not be coalesced. Segment lengths sum exactly to 4,294,967,296. Every supplied route and probe survives in JSON, including uncovered probes and wholly shadowed routes. Address counts include network/broadcast addresses and are **not usable-host counts**.

A first-matching-row baseline intentionally illustrates a common spreadsheet shortcut; it is not a realistic router algorithm. Probe comparisons are computed checks against supplied intent, not model accuracy, automatic repairs, performance measurements or time-saving estimates. The office fixture has 2/3 baseline mismatches versus 0/3 longest-prefix; the warehouse fixture has 3/3 versus 1/3 because its external probe is uncovered under either algorithm. AI reconciles identity only; exact forwarding analysis is deterministic.

This is hypothetical single-table IPv4 destination forwarding. No ECMP behavior, policy/source routing, administrative-distance protocol selection, recursive next hops, interface status, IPv6, firewall policy, dynamic updates or live reachability is modeled. Metrics are assumed comparable within a prefix. Fully shadowed means never uniquely resolved to that route's gateway under these assumptions, not permission to delete it. No scanning, network testing, configuration generation or device changes.
