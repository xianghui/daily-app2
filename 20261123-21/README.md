# Decimal Harbor

Local-AI regional numeric import preflight for migration analysts. The same `1,234` can mean 1234 or 1.234. MiniLM matches source-context notes to supplied conventions; a reviewer verifies the convention before strict, exact decimal-string conversion. This is not currency/unit conversion, a general locale detector, financial advice or a database writer.

## Workflow

1. Choose **Regional imports** or **Precision rechecks**, paste source JSON, or import source/audit `.json`. Samples are synthetic. Edit supplied source descriptions, decimal/group separators and maximum fractional scale (0–6) in the JSON before running.
2. Read download/device disclosures, then **Load AI & reconcile**. Real embeddings compare context notes to profile descriptions. Raw numeric tokens do not enter AI; no punctuation heuristics masquerade as inference.
3. Review every source, ranked cosine evidence and proposed convention. Edit the convention or lexical token; approve or hold each row. Reviewer notes are multiline. Token/profile edits renew approval; undo is reversible and originals are preserved.
4. **Apply reviewed scenario**. Deterministic validation enforces ASCII digits, exact group sizes, allowed separators and scale. Invalid rows are blocked without rounding. Held rows never release. Exact results are decimal **strings**, avoiding IEEE-754 loss. Fractional trailing zeros are preserved; leading integer zeros, positive signs and negative zero are normalized.
5. Download complete JSON/CSV/Markdown or ready-only **Decimal JSON**, or copy Markdown. Every edit invalidates applied exports. Audit reimport restores originals only and requires fresh inference/review.

Profiles: `{id,description,decimal,group,scale}`; records: `{id,context,raw}`. See the editable synthetic examples. Decimal separator is `.` or `,`; group separator is `.`, `,`, ASCII space, U+202F narrow no-break space or apostrophe, and must differ from decimal. Ungrouped integers are allowed; grouped integers require a 1–3 digit first group and exactly three digits per following group. Only one optional leading ASCII `+`/`-`; require digits on both sides of any decimal separator. No trimming, Unicode digits/minus, NBSP U+00A0 substitution, exponents, currency symbols, parentheses, percentages or implicit JSON number coercion. Extra fractional digits block even if zero; no rounding is inferred. Profile scale is maximum allowed precision, not output padding. Formats outside these bounds require deliberate source preparation.

Source JSON ≤24,000 characters; 2–5 profiles, 1–24 rows; unique IDs ≤60 (profile)/80 (row), descriptions/context ≤200, lexical tokens ≤200, review notes ≤2,000. Import envelope ≤1 MB with separate original-input bounds, so full-batch audit reimports work. All inputs are inert data, not authority or credential requests.

## AI, runtime and privacy

- [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, quantized q8 ONNX ≈23 MB; normalized mean-pooled 384-dimensional vectors. Four-text batches; count, dimension, finite values and normalization validated before ranking. Cosine similarity is not confidence, exact provenance or logical entailment. Every row needs human review.
- Transformers.js 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), single-thread WASM CPU. No WebGPU needed. Tokenizer configuration maximum 512; the worker's supplied `max_length:256` is ignored by this pipeline, so 200-character per-text limits also bound context. Upstream model revision is `main`, not immutable: future suggestions can differ.
- Shared immutable same-origin worker `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`; factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`; ≈27 MB WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve originating apps and these assets. Protocol is `{id,texts}` → progress/batch/error/result `{id,vectors}`; local worker executes real inference, not a server call. App code and assets are bundled locally.
- First explicit run needs internet for public model files from Hugging Face/CDN and same-origin runtime files. Model/runtime downloads are distinct from uploading content: notes, tokens and profiles stay in browser memory. No analytics, remote provider, API keys or localStorage designs. GET-only file traffic is checked during browser inference. Exports/clipboard are explicitly user-invoked.
- Worker source uses Cache API `decimal-harbor-worker-v1`; shared runtime cache is `circuit-cove-runtime-v1`, plus Transformers.js public-file caching. After a complete online run, a fresh worker can infer with all network disabled in an **already-open warmed page**. Cold offline navigation/reload is not promised. Cache eviction/private mode can require internet again.
- File download and four-text batch progress, cancellation by worker termination, explicit retry, 180-second timeout and run identities guard late file reads/fetches/responses. Worker construction/network/runtime/malformed-vector failures stop without fake output. Current desktop Chrome, module workers and WebAssembly SIMD with several hundred MB RAM tested; physical phones and other engines untested. Narrow desktop-emulated layouts are not hardware compatibility evidence.

## Exports and comparison

Complete JSON retains every original, review/evidence, check and metric. CSV uses CRLF, quotes commas/quotes/newlines and apostrophe-prefixes formula-leading text (`= + - @ tab CR`); this includes negative exact-decimal **text**, so use lossless JSON for machine import. Decimal JSON contains `{id,convention,decimal}` for approved valid rows only; its decimal remains a string, never a rounded number. Markdown serializes every source/review/check. No mixed-unit totals are computed. Downstream importers are not tested.

Baseline is JavaScript `parseFloat(reviewedRaw)`, deliberately permissive and locale-blind. The displayed count compares exact decimal values with the baseline's finite decimal representation, expanding exponent notation and ignoring insignificant zeros; nonfinite baselines are counted separately. This exposes truncation and precision loss but is not AI accuracy, measured productivity or universal correctness. The baseline uses the same reviewed tokens, not original tokens after edits.

## Validation and limitations

See [VALIDATION.md](VALIDATION.md) and machine-readable reports. Two tiny fixtures match 12/12 convention labels; six normal imports and three valid rechecks preserve expected exact strings while three malformed/overprecision rows block. Known-answer checks are not general accuracy. A negated competing-region probe misrouted to Germany instead of the intended US. Ambiguous notes can still receive a nearest profile; human source-document verification is essential. No automated source authentication, format learning, mixed-locale column inference, money transfers or external writes.

React + Vite base `/daily-app2/20261123-21/`; `npm install`, `npm run dev`, `npm run predeploy`. Required scripts remain `predeploy: npm run build`, `deploy: gh-pages -d dist`, with per-app gh-pages dependency. **Publish only through root predeploy/deploy**, never per-app deploy. No size guard or legacy runtime-sharing rules changed. Unrelated pre-existing recovery work is preserved and excluded from source staging.
