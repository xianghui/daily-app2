# Origin Ledger

A local-first CORS handoff workbench for integration engineers. Input informal client-purpose notes plus supplied request/response snapshots; real neural client matching resolves aliases; mandatory review produces actionable browser-response QA fixtures. No endpoints are called. This is distinct from the collection's robots, HTTP retry, range, negotiation and conditional-write utilities.

## Use

1. Choose **Dashboard & account** or **Preflight edge cases**, paste source JSON, or import an audit JSON. Only originals are restored on reimport; approvals must be renewed.
2. Edit `plans`: unique ID, English semantic description, canonical HTTP(S) origin with no slash/path, and credentials `omit` or `include`. These are explicit user contracts, not AI-generated security policy.
3. Records contain unique `id`, short `context` and a `raw` JSON string. See `src/core.js` for synthetic source examples. Raw objects have exactly `method`, `headers`, `response`, `preflight`. Response has `allowOrigin`, `allowCredentials`; empty strings mean absent. Preflight is null or `{status,allowOrigin,allowCredentials,allowMethods,allowHeaders}`. Arrays represent already-parsed response header lists, not raw HTTP lines. Header strings should be parsed/OWS-trimmed values. Do not include real credentials.
4. **Load AI & reconcile** explicitly downloads and runs the default no-key model. Inspect all ranked similarity scores (not probabilities), profile details, original context and preserved snapshots. Change the profile or request, write multiline notes, approve or hold each case. Undo restores the last review edit; edits invalidate export snapshots and profile/request edits reset approval.
5. **Apply reviewed scenario** computes checks. Malformed snapshots are blocked but preserved; held records have no released fixture. A valid denied request is useful as an expected-denial fixture and is included when approved.
6. Download complete audit **JSON**, formula-protected **CSV**, **Markdown**, or ready-only **Release JSON** fixtures; copy the reviewed worksheet. Artifacts reflect the applied current review, not a sample. Reimport complete audit JSON restores exact originals. No requests/configuration changes are performed.

## Real AI and why it helps

`Xenova/all-MiniLM-L6-v2` q8, [model/source](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0; Transformers.js **4.3.2**, Apache-2.0; ONNX Runtime Web WASM CPU, MIT. Normalized mean-pooled **384-dimensional** vectors compare each English client-purpose note with user-authored descriptions. The highest cosine candidate is a pending suggestion, not an automatic approval. Semantic aliases can match without exact profile IDs. No generative response, credentials, fake model, paid service or remote content inference is used.

Initial download: approximately **23 MB weights + 27 MB WASM** plus tokenizer/factory/code. Internet to Hugging Face/CDN and this same-origin static site is required before caching. Explicit loading, download status and chunk progress are shown; cancellation terminates the worker. Runtime/worker downloads use Cache API; Transformers.js caches model files. Storage may be unavailable or evicted. Actual offline scope tested: a **new worker in an already-open, warmed page**, not cold offline reload/navigation or guaranteed persistent installation. Current desktop Chrome with module workers and WebAssembly SIMD, several hundred MB spare RAM recommended. No WebGPU needed; other engines/physical phones are untested. Runtime/device/network errors are actionable and never produce deterministic pretend-AI output.

Shared immutable source worker: `20261115-6/assets/ai.worker-lkOoPoq8.js`; module factory: `20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`; WASM: `20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve those earlier apps. See `runtime-provenance.json` for bytes/hashes; no duplicate runtime is shipped. The shared worker batches four texts. Its feature-extraction `max_length:256` argument is **not** claimed to enforce a tokenizer cap; model tokenizer `model_max_length` is 512, and this app independently bounds contexts/descriptions to 200 characters.

## Deterministic subset and limits

After human client review, deterministic code determines whether a preflight is required, whether supplied snapshots permit method/header use and credentialed response access, and why. Assumes cross-origin requests and no preflight cache. Credentials `include` itself does not force preflight; when it applies both actual and preflight origins must exactly match and Allow-Credentials must equal `true`. Wildcards authorize methods and headers only for `omit`. Safelisted GET/HEAD/POST do not need to appear in Allow-Methods even after header-induced preflight. Preflight status must be 2xx. Both preflight and actual response are independently checked.

Supported authored headers: **Content-Type and X-* only** (excluding browser-special X-HTTP-Method, X-HTTP-Method-Override and X-Method-Override), printable ASCII values ≤256 characters, at most eight unique case-insensitive names. Content-Type is safelisted only with supported essence (text/plain, multipart/form-data, application/x-www-form-urlencoded), ≤128 characters and no CORS-unsafe bytes. Other headers, notably Authorization, are rejected with actionable guidance. During development Chrome 157 accepted wildcard Authorization permission where our conservative standards check rejected it; rather than publish a browser prediction known to differ, Authorization was removed from this utility's supported input subset. The final 32-case actual-browser oracle covers the supported subset and all matched. Header snapshots are parsed structured fields, not an HTTP parser.

Methods: uppercase GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS. Null/opaque origins, same-origin requests, credentials same-origin, redirects, service workers, cookies blocked by browser policy, private-network access, exposed response headers, preflight cache and full browser/network behavior are outside scope. **Denied means response access fails these checks, not that no request can be sent. CORS is not authentication, server authorization or CSRF protection.** This is a bounded QA aid, not security certification or a replacement for live integration tests.

2–5 profiles; 1–24 records; IDs ≤60/80 characters; descriptions/contexts ≤200; raw cases ≤3500; source ≤50,000 characters; import ≤1 MB; notes ≤2000. Preflight methods ≤10, allowed headers ≤16. Input is inert text, never tool authority. Finite normalized vector count/dimensions are validated. Run IDs cover input changes, asynchronous imports and worker-source fetches; cancelled/late results cannot replace newer work. Timeout 180 seconds; recover using cancel/retry or a fresh supported browser/network. Originals remain intact.

Baseline checks only the actual Allow-Origin (wildcard or exact), ignoring credential and preflight checks. Displayed counts compare approved valid decisions using the **same reviewed clients**, not benchmark accuracy or measured time savings. No invented confidence, performance or security claims. Tiny known-answer fixtures and a negation failure are documented in VALIDATION.md.

## Privacy

Source notes, snapshots, embeddings, reviews and artifacts stay in this browser memory unless the user downloads/copies them. Network transfers only load model/runtime files; no user-content upload or analytics, no provider integration, and no API key storage exists. Do not paste actual cookies or tokens. Examples are synthetic `.example` data. Downloads may contain sensitive user-added content, under the user's control.

## Development and deployment

React + Vite. `npm install`, `npm run dev`; required `npm run predeploy` builds `dist`. Per-app deploy is `gh-pages -d dist` for contract compatibility, **not** the collection publishing path. Publish only from the repository root with its existing combined `deploy/` assembly. Vite base `/daily-app2/20261124-18/`.

The collection's unchanged 1 GB guard needs one additional byte-identical legacy geometry-runtime reuse (`20261106-9` → `20261028-24`). This only rewrites assembled URLs; source builds and compatibility JS paths remain intact. New and affected older app runtime/import/export paths must pass assembled/public checks. See validation records for observed outcomes and publication status.

Validation harnesses use the workspace-installed Playwright/Chrome, not a production dependency. With the combined deploy tree assembled, start `python3 serve-production.py`, then run `node core-test.mjs`, `node cors-oracle.cjs`, `node browser-test.cjs`, `python3 artifact-test.py`, `node defensive-test.cjs`, `node model-network-test.cjs`, `node async-race-test.cjs`, `node stale-success-test.cjs`, `python3 asset-test.py`, `node gallery-test.cjs`, `node gallery-browser-test.cjs`, `node legacy-test.cjs` and `python3 static-test.py`. Browser suites accept APP_URL/PREFIX or SITE_BASE for public checks; asset tests accept ASSET_BASE. Do not run suites while root predeploy is clearing the deploy directory. `cors-oracle.cjs` uses separate loopback ports 7559/7560 solely for synthetic protocol verification.
