# Merge Lantern

A local-first configuration handoff workbench for integration engineers. Match informal change notes to a small catalog of **saved JSON snapshots**, review the target and supplied merge patch, then export deterministic RFC 7396 test cases. No API calls, deployments, credentials or filesystem modifications.

## Workflow

1. Choose either synthetic example, paste source JSON, or import a source/audit `.json` file (≤1 MB).
2. `plans`: 2–5 `{id, description, target}` snapshots; `target` is a JSON **string**. `records`: 1–24 independent `{id, context, raw}` requests; `raw` is a JSON merge-patch **string**. This string representation keeps malformed patches reviewable instead of silently dropping them.
3. Read download/privacy notices, explicitly click **Load AI & reconcile**, watch download/chunk status, or cancel.
4. Review each proposed snapshot, cosine ranking evidence, original target, patch, result and JSON Pointer change witnesses. Edit patches/notes, correct target links, approve or hold. Every target/patch edit renews approval; every edit invalidates the export snapshot. Undo is available for the last 100 review edits.
5. Apply the reviewed scenario. Pending decisions block application. Invalid approved cases stay blocked and visible; held cases are retained but excluded from fixtures.
6. Download complete JSON, CSV, Markdown or approved-only **Fixtures JSON**, or copy the Markdown worksheet. Fixtures contain `{id,snapshot,mediaType,target,patch,expected}` with media type `application/merge-patch+json`. These are independent dry-run tests, **not** RFC 6902 operation arrays or live commands. Reimport an audit to restore original inputs only and renew inference/review.

## Real AI and why it helps

`Xenova/all-MiniLM-L6-v2` quantized q8 (Apache-2.0), via Transformers.js **4.3.2** (Apache-2.0), ONNX Runtime Web WASM CPU (MIT). Model source: https://huggingface.co/Xenova/all-MiniLM-L6-v2 . Actual normalized mean-pooled 384-dimensional embeddings rank each English change note against snapshot descriptions. This semantically resolves paraphrases instead of requiring exact identifiers. Snapshot JSON and patch values are never generated by the model. Original descriptions and note snippets plus cosine scores are shown; scores are **not confidence probabilities**.

First use requires internet and approximately **23 MB model weights + 27 MB WASM**, plus tokenizer, worker and module factory. Model files download from Hugging Face and its CDN (observed `huggingface.co`, `us.aws.cdn.hf.co`). No model request precedes explicit loading. The tokenizer model cap is 512 tokens; the worker's `max_length:256` option is **not treated as an enforced cap**. This app bounds every model text to 200 characters and runs four texts per chunk. English-oriented similarity can fail on negation, subtle policy distinctions, ambiguous or overlapping descriptions. Mandatory review is essential; tiny fixture performance is not general accuracy.

Default execution is local CPU inference, not a heuristic or canned answer. No key, paid service, remote-provider option or server required. No WebGPU required. Use current desktop Chrome with module workers, WebAssembly SIMD, secure origin, several hundred MB free RAM and Cache API for offline reuse. Other engines and physical phones remain untested. Unsupported environments and network/model failures show actionable errors; no deterministic fake AI fallback. Timeout is 180 seconds; cancellation terminates the worker. Run identities protect input changes, pending file reads, worker fetches and late responses.

## Shared immutable production assets

To avoid duplicating the nearly full collection's runtime, this app uses the existing same-origin worker at `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`, its factory `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`, and WASM `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. **Preserve both originating apps and paths.** `runtime-provenance.json` records actual sizes and SHA-256 hashes, independently verified in production asset audits. Those older worker sources are the canonical model/runtime implementation. The new React app has no CDN JavaScript imports or server dependencies.

The app caches worker source (`merge-lantern-worker-v1`); the shared worker caches factory/WASM (`circuit-cove-runtime-v1`), and Transformers.js caches model files. Browser eviction/private mode can remove or disable caches. Offline scope is deliberately narrow: **a fresh worker can run inference in an already-open, warmed page after an online run**. Tested by blocking all network. Cold offline navigation/reload is not supported. Downloading model bytes does not upload your notes, snapshots or patches. Content/reviews remain in page memory unless exported; model/runtime caches do not contain input text. Do not paste secrets. Browser request inspection checked GET-only, no request bodies and no source text in URLs; sanitized audit logs retain hosts/paths/query-key names only, never signed CDN parameter values.

## Deterministic contract and limits

RFC 7396 merges object members recursively; member null deletes, absent members survive, arrays/scalars replace in full, and root null replaces the entire document. Empty-object patches turn non-object targets into objects. Every record uses its selected **original** target independently, never a preceding record's result. There is no schema/business-rule validation, stale-server check, credential handling or endpoint execution. Setting an object member to literal null is not expressible with merge patch.

Limits: 2–5 snapshots, 1–24 records; IDs ≤60/80 characters; descriptions/context ≤200; target JSON string ≤6000; patch JSON string ≤2500; each parsed value ≤500 nodes and depth ≤8; source ≤50,000 characters; file ≤1 MB; notes ≤2000. Only finite JSON numbers are accepted; do not use values requiring exact integers beyond JavaScript's safe-integer range. Duplicate JSON keys follow `JSON.parse` last-key behavior; avoid them. Prototype-related object keys (`__proto__`, `constructor`, `prototype`) are blocked at any depth. Imported content is data, never instructions or executable markup.

Comparison: object/object approved cases only, deterministic RFC 7396 output versus shallow object spread. Counts of ready/held/blocked cases, change witnesses, comparable cases and differing results are computed from current reviews. A change witness is a recursive replacement/deletion/coercion event, **not an exact changed-leaf count**. Non-object pairs lack a shallow-object baseline and are excluded, never allowed to suppress valid output. No invented time savings or accuracy percentages.

JSON and Markdown retain exact originals/reviews; CSV quotes commas, quotes and newlines and prefixes formula-leading strings with `'`. JSON remains the lossless audit. Held/blocked records remain in all audits, not the approved fixture release. Copy/download always uses the latest applied reviewed snapshot; edits disable exports until reapplied.

## Build and publishing

React + Vite. `npm install`, `npm run predeploy` builds with base `/daily-app2/20261125-1/`. Required per-app scripts remain `predeploy: npm run build`, `deploy: gh-pages -d dist`; **do not use the individual deploy** because it would replace the collection. Publish via `/Volumes/ExternalHD/daily_app2`: root `npm run predeploy`, then `npm run deploy`. Root gallery/runtime asset paths are required for inference. The app's independent oracle dev dependency `json-merge-patch` is used by tests only, not the bundle.

## Validation and limitations

See [VALIDATION.md](VALIDATION.md) for observed browser/model/artifact/public results, failures fixed and untested scopes. Tests use only synthetic fixtures. `node oracle-test.cjs` checks the RFC examples and 500 generated cases against independently implemented `json-merge-patch`; actual browser downloads are parsed with Python csv/json and checked against that library too. Browser suites require the existing local Playwright package and installed Chrome; use `APP_URL` and `PREFIX` for assembled/public runs. Screenshots cover 1440/390/320 CSS pixels; physical touch hardware is not tested.
