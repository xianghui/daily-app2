# Triangle Harbor

A warranty operations analyst consolidates repair-payment triangles from different teams. The costly ambiguity is whether each development column contains **only that period's payments** or **the cumulative total since inception**. AI retrieves the closest user-supplied basis description from each short handoff note. Review the suggestion and actual source-system definition, edit values, approve or hold, then apply to produce a source-linked development worksheet. This is not a generic chat interface and it does not use model inference to invent amounts.

## Use and formats

Choose either synthetic example, paste a source JSON object or import `.json`. The examples are entirely synthetic. `title`, three-letter `currency`, `profiles` (id, description, rule incremental/cumulative) and `requests` (id, note, cohorts, cells) are required. There are 2–6 profiles and 1–24 triangles. Each has 2–6 uniquely labeled cohorts, oldest first, with rows of lengths N, N−1, …, 1. Use equal development ages across cohorts. Missing future cells are omitted, not zeros. Every numeric cell is a nonnegative integer **string in minor units**, up to 12 digits. Descriptions/notes max 200 characters, cohort labels 60, raw JSON 60,000 characters. File imports max 1 MB, including full audit envelopes. Unique ASCII IDs are required. The model sees descriptions/notes only, not numeric values.

Run **Load AI & suggest basis**; this explicitly authorizes asset downloads, not content uploads. Review every profile, cell array and decision. Candidate cosine scores are similarity, not confidence. Correct the basis, edit cells, add multiline review notes or hold/reject. Bulk approval is an explicit reviewer action, never automatic. Undo restores the previous review (100 snapshots). All edits and source changes invalidate applied exports. Source changes/cancellation terminate workers; asynchronous imports/downloads and worker messages use run identities to reject stale data.

Apply the current review. Held triangles remain in every audit and block a complete batch release; valid triangles remain partial diagnostics. Zero matched development denominators and decreasing cumulative totals block calculations. Invalid reviewed JSON/shape cannot apply. Originals always remain intact. JSON includes originals, review, candidates, normalized cumulative triangles, exact factors and cohort estimates. CSV preserves every triangle; Worksheet CSV includes one row per cohort or a held/blocked placeholder. Markdown/clipboard provide a handoff. Exports reflect only current applied reviews. Reimporting audit JSON restores **original inputs**, not approvals. Formula-like CSV text beginning `= + - @ tab CR` is apostrophe-prefixed, including multiline cells; integer values/fractions are retained as strings. Closing the page loses unsaved work.

## Actual AI, source, license and static runtime

- Model: [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, quantized q8. Approximately 23 MB model weights plus tokenizer/config.
- Runtime: Transformers.js **4.3.2**, ONNX Runtime Web, mean pooling and normalized **384-dimensional** embeddings, single-thread WASM CPU. No WebGPU or API key needed. Batches of four texts, max 30 texts; finite count/dimension/unit norm are validated before retrieval. Tokenizer `model_max_length` is 512; the shared pipeline does not forward its `max_length:256` option, so we claim 512, not 256. Character bounds are separate; unusual text may truncate.
- Current Chrome desktop, module workers, WebAssembly SIMD, BigInt and sufficient RAM required. Tested with GPU disabled. Physical mobile devices/other browser engines are not verified. A CPU/runtime failure gives an actionable error, not fake output. 180-second timeout, progress, cancel and retry.
- Initial download approximately **50 MB** (23 MB model + 26,861,777-byte WASM, plus JS/tokenizer). Model comes from Hugging Face/CDN; runtime assets are same-origin. Model revision is not pinned, so upstream changes can affect future inference.
- This app reuses immutable byte-identical published runtime from `20261115-6/assets/ai.worker-lkOoPoq8.js`, `20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs` and `20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`. Preserve those older apps/paths in combined deployment. Hashes in `runtime-provenance.json`; no copying 27 MB per new app. The shared compiled worker is the actual browser runtime, not a mock.

## Privacy and offline scope

Default processing is entirely in a browser worker; no server inference, API credentials, analytics or remote actions. User notes/numbers are not sent to the model host. Imported strings are data and do not execute tools or request credentials. Cache API stores model/runtime assets, **not user documents**. Worker source is cached and loaded as a blob module; factory and WASM are explicitly cached. Eviction, private browsing or denied caching may require downloads again. Tested offline scope: **fresh-worker real inference in an already-open warmed page**, after all networking is disabled. Offline app navigation/reload/cold startup is not promised. Browser request capture checks all traffic from page startup through inference and exports; only GET asset downloads with no bodies are permitted. No optional remote provider integration exists.

## Deterministic method and assumptions

After human review, incremental rows are cumulatively summed; cumulative rows are preserved and must not decrease. For development age j, the volume-weighted factor is the sum of observed cumulative payments at j+1 divided by the sum at j, **using only cohorts with both ages observed**. Each cohort's latest observed paid amount is multiplied by the remaining selected factors to estimate ultimate paid. Unpaid = projected ultimate − latest paid. All arithmetic uses reduced BigInt rational fractions; latest + unpaid = ultimate is asserted exactly. Factor numerators, denominators and contributing cohort indexes are exported. Display approximations truncate at two decimal **minor units**, not major currency units; exact fractions govern exports.

The baseline treats the same reviewed triangle as already cumulative. Incremental handoffs therefore expose a genuine interpretation difference; often the shortcut is invalid because its supposed cumulative payments decrease. Baseline errors do not suppress valid reviewed projections. No percentage accuracy, savings or predictive-quality claims are made. This is chain-ladder-style **planning**, with the last supplied development age assumed fully mature, no tail factor, stable homogeneous settlement patterns, no negative payments/recoveries, exposure/inflation adjustment, discounting, standard errors or probabilistic model. A sparse/shifted portfolio can produce misleading projections. This is not an actuarial opinion, approved accounting reserve or account posting.

## Limits of AI

Nearest-match embeddings always select a supplied profile, including for irrelevant, mixed or contradictory notes. Simple fixture performance does not establish real-world accuracy. The actual negation probe selected incremental when the note explicitly meant cumulative. Irrelevant/mixed notes also received arbitrary matches and must be held. The model cannot validate accounting semantics, maturity, homogeneity, currency or development periods. Human source verification is mandatory. Never act financially based solely on this worksheet.
