# Caption Folio

A small-batch exhibition label desk for coordinators reconciling informal installation lists with catalog records. **Input → real semantic retrieval → mandatory human review → print checks → printable HTML and complete audit.** No generic chatbot, generated provenance, image identification, uploads or publishing actions.

## Workflow / formats

Choose either synthetic exhibition, paste source JSON or import a `.json` source/audit (8 MB maximum envelope). Source fields: `title`, `captionLimit` (40–600 Unicode code points), `profiles` (2–8 catalog entries) and `records` (1–12 label requests). Each catalog entry has a unique `id`, short `description`, `title`, `maker`, `date`, `medium`, and `credit` (may initially be empty). Each request has a unique `id`, short `note`, and `location`. See `src/core.js` for examples and exact schema validation. Bounds: 30,000 source UTF-16 units, 200 per neural text, 120 per catalog copy field, 200 credit, 80 location, 600 editable caption, 500 reviewer note. Control characters and unpaired surrogates are rejected; newlines and valid Unicode are supported. Caption policy counts code points within the separate 600 UTF-16-unit editor limit.

Explicitly load AI. Inspect ranked catalog descriptions, correct links, edit any label field and write an optional human-authored caption. No captions are generated by AI. Changing a link reloads the five catalog copy fields and resets approval; it retains the caption for further review. Approve or hold every label. Bulk approval is explicit and should follow review. Undo retains 40 review snapshots; original source is always kept. Source edits stop the old worker and invalidate results. Review edits invalidate applied/export snapshots.

Apply reviewed labels. Duplicate approved object links, missing credits, captions above your policy limit or held requests block **Print HTML**; audits remain exportable. This workflow intentionally supports one label per object, not repeated labels for one object. Credit presence is not verification of authorship, ownership or reproduction rights.

Download complete **JSON**, **Audit CSV**, **Markdown**, or approved **Print HTML**. JSON round-trips original inputs; import deliberately does not restore approval authority. CSV preserves every source request and reviewed field; spreadsheet-formula-leading string cells receive an apostrophe, including multiline cells. JSON remains lossless. Markdown is a plain-text handoff, not trusted HTML. Copy uses the current applied Markdown. Print HTML contains escaped text, no scripts or external assets, a restrictive CSP and responsive two-column/A4 print styles. Open it in a browser and use Print preview; label heights vary with copy. Browser PDF rendering was checked; physical printer margins, cutting and final output are unverified.

## Real AI / model / runtime / data flow

Default `Xenova/all-MiniLM-L6-v2` q8, Apache-2.0: https://huggingface.co/Xenova/all-MiniLM-L6-v2 . Transformers.js 4.3.2 (Apache-2.0), ONNX Runtime Web (MIT), WebAssembly CPU, one thread, mean-pooled normalized 384-dimensional neural embeddings, batches of four. Cosine ranking retrieves supplied catalog descriptions from paraphrased installation notes; it materially selects the catalog record supplying label copy. Similarity is **not** confidence or an identity/rights guarantee. No hard-coded responses or deterministic fallback. Unrelated notes always force a nearest match; negation may be wrong. Mandatory review remains essential.

Runtime assets are existing immutable same-origin collection files, not CDN-loaded application code:

- `../20261115-6/assets/ai.worker-lkOoPoq8.js`
- `../20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`
- `../20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`

Preserve those older builds/paths. `runtime-provenance.json` records hashes/sizes. Reviewed worker uses `{id,texts}` → progress/batch/result vectors/error, groups of four, CPU-only runtime. Model files use the hosted main revision; runtime hashes do not pin upstream weights. Input text is independently short-bounded rather than relying on the runtime's truncation options.

First load roughly 50 MB: ~23 MB weights plus 26.86 MB WASM and JS/tokenizer/factory. Initial internet required; Hugging Face/HF-Xet CDN serves model files, this origin serves runtime. No model downloads before clicking Load AI. Current desktop Chrome/Edge with WASM SIMD, module workers and Cache API recommended; no WebGPU needed. Visible file/batch progress, cancellation, retry and a 180-second timeout. Unsupported/runtime/network/malformed-output errors produce no fake results.

Content stays in browser/worker memory. No credentials, providers, telemetry, storage of content or external actions. Catalog text is data, cannot grant tools or request credentials. Runtime/model caches store public download files only. After a successful online load, new-worker inference works with networking disabled in the **already-open warmed production page**. Offline reload/navigation/app-shell startup is not promised. Cache eviction/private mode/denied storage can require a new download. Browser-network audit persists only hosts/paths and query-key names, not temporary CDN tokens.

## Deterministic checks and honest comparison

Exact-title baseline: a request note equals exactly one catalog title after trim/lowercase. It deliberately represents a simple exact lookup, not a human accuracy benchmark. Displayed beyond-exact count is approved links not supplied by that baseline, a coverage count **not accuracy, elapsed time or savings**. Human edits also affect that count. AI quality is evaluated separately on four known-answer synthetic object notes; it is not a representative museum benchmark. Deterministic print checks do not certify factual attribution, suitability or rights.
