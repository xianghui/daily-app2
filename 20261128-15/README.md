# Divider Bench

A local-AI worksheet for **low-voltage prototype/teaching bench coordinators**. Informal instrument handoffs often omit the effect of the receiving instrument's input resistance. This desk retrieves a supplied instrument load from the handoff meaning, lets a human verify it, then searches offered resistor pairs under explicit nominal output/current/power constraints. It is not a chat wrapper, hardware controller or circuit certification tool.

## End-to-end workflow

1. Choose **Meter & scope** or **DAQ & panel** (synthetic), paste source JSON, or import a `.json` source/audit ≤1 MB. Edit the offered resistor list, instrument catalog and per-job goals/limits.
2. Explicitly **Load AI & match instruments**. No model-host download occurs before this action. Observe download and chunk progress; cancel or retry. Content is processed in a local module worker.
3. Inspect each source note, instrument description and cosine score (similarity, **not confidence**). Correct the profile or verified input resistance, supply, target, allowed output error, current/power bounds and old resistors. Changes to electrical fields require reapproval. Approve or hold/reject every row; add multiline notes; undo up to 30 edits.
4. **Apply reviewed worksheet**. The resulting snapshot is the only export source. Any edit invalidates it. Complete JSON, audit CSV and Markdown retain every approved/held/infeasible job. **Bench CSV** is gated until every job is approved and a feasible offered pair exists. Copy uses current applied Markdown.
5. Reimporting an audit restores original inputs, never old approvals. There is no autosave: export before closing. No physical resistors, files or accounts are changed.

## Exactly what the real AI does

[Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), Apache-2.0, q8 ONNX, produces normalized mean-pooled **384-dimensional sentence embeddings** for catalog descriptions and job notes. Cosine ranking reconciles informal language with supplied instrument identities. The selected identity materially changes the load impedance and therefore the feasible voltage-divider pairs. No electrical constants are generated by AI. Vector count, finite dimensions and approximate unit normalization are validated before ranking.

Runtime: Transformers.js **4.3.2** (Apache-2.0), ONNX Runtime Web (MIT), single-thread **CPU WASM** with SIMD/module workers; WebGPU not needed. No API key, account, paid service, optional provider, remote inference, hard-coded inference result or deterministic demo fallback exists. All equations, feasibility checks, ranking tie breaks, review decisions and exports after embedding are deterministic.

Initial explicit load is approximately **50 MB**: ~23 MB model/tokenizer from Hugging Face and its CDN plus ~27 MB same-origin runtime. Internet is required initially. Model upstream `main` is not pinned; observed resolved config/tokenizer revision was `751bff37182d3f1213fa05d7196b954e230abad9`. Requests are documented in validation reports with signed query values stripped. The fixed runtime is byte-audited in `runtime-provenance.json`.

Supports modern WASM SIMD/module-worker browsers with adequate memory. Tested: desktop Chrome, GPU disabled, including 320/390-pixel responsive emulation. Physical phones, memory-constrained hardware and other browser engines are **unverified**. 180-second timeout, network/runtime/schema errors are visible; failure never invents a match. Run identities, aborted fetches, terminated workers and file-read identities prevent cancelled/stale results from replacing current input/results.

## Static hosting, privacy and cache scope

App JS/CSS are same-origin bundles. To avoid duplicating ~27 MB per app, the inspected immutable worker and runtime are shared:

- `/daily-app2/20261115-6/assets/ai.worker-lkOoPoq8.js`
- `/daily-app2/20261115-6/runtime/ort-wasm-simd-threaded.asyncify.mjs`
- `/daily-app2/20261107-2/assets/ort-wasm-simd-threaded.asyncify-CxOG5pUO.wasm`

**Preserve those older app paths.** The worker protocol is `{id,texts}` → progress/batch/error or `{id,type:'result',vectors}`. The worker caches the WASM factory/binary, the app caches worker source, and Transformers.js caches model files. The worker's actual model call uses pooling `mean`, normalization and CPU q8. Its pipeline `max_length` option is not advertised as a separately enforced tokenizer cap; the app bounds each text to 200 characters and at most 20 texts, in chunks of four.

**Default user content stays on-device.** Network capture from app startup through inference showed only GET asset downloads with no request bodies and no fixture text in request URLs. Downloading model weights is not uploading handoffs. There are no analytics, credentials or provider integrations. Imported prompt-like instructions remain embedded text; they cannot invoke tools or request passwords. Credential-pattern scans supplement manual integration inspection rather than proving absence of every possible secret.

Tested offline scope: complete one online inference, terminate the worker, disable all network, then create a fresh worker and perform real inference in the **same already-open warmed page**. Offline reload/navigation is not supported or claimed; there is no app-shell service worker. Storage denial/eviction means another network download is needed.

## Source schema and limits

`{title,resistors,profiles,records}`. Valid source ≤30,000 characters; imported envelope ≤1,000,000 bytes. Title 1–100 characters. IDs are unique simple `[-A-Za-z0-9_]{1,24}` within each table. Notes/descriptions 1–200 characters. No forbidden controls or broken Unicode. Reviewer notes ≤1,000 characters, multiline allowed.

- `resistors`: 2–24 distinct offered nominal values, **100–10,000,000 Ω**. Each value may be used in either/both legs; inventory quantity is not modeled.
- `profiles`: 2–8 `{id,description,loadOHM}` entries; resistive DC input **100–1,000,000,000 Ω**. Supplied illustrative numbers are not specifications of any actual instrument.
- `records`: 1–12 `{id,note,vin,target,tolerance,currentCapMA,powerCapMW,oldTop,oldBottom}`. `vin` .1–24 V; target .05–23 V, strictly below supply; tolerance .1–20%; supply-current cap .001–50 mA; each divider resistor's nominal power cap .01–500 mW; old resistor values 100–10,000,000 Ω. Finite numeric values required. Review adds verified `profileId`, `loadOHM`, decision and note.

JSON retains every source, review, candidate score, selected pair and baseline. CSV contains every job, original note and current reviewed electrical fields; quotes/commas/newlines are escaped using CRLF rows and doubled quotes. Formula-like string fields starting `= + - @ tab CR` receive an apostrophe, including multiline text. Numeric fields remain numeric. Markdown is exported/copied as text and never rendered imported markup. Audit import restores **original** values, not modified review fields.

## Deterministic objective and baseline

Let `Rt` be the upper resistor, `Rb` the lower resistor, and `RL` the receiving instrument's DC input resistance:

```
Rp = 1 / (1/Rb + 1/RL)
I_supply = Vin / (Rt + Rp)
Vout = Vin * Rp / (Rt + Rp)
P_upper = (Vin - Vout)^2 / Rt
P_lower = Vout^2 / Rb
```

Enumerate both legs from the finite offered list (≤576 pairs/job). Retain only pairs with output within `target ± target*tolerance/100`, supply current within its cap and **both divider resistor** powers within the entered per-resistor cap. Choose lowest supply current; ties favor smallest absolute target error, then smaller upper/lower values via ascending stable enumeration. No feasible pair means blocked, not relaxed constraints.

The baseline is the **entered old pair** calculated under the same reviewed load and limits. Report its bound failures. An unloaded-only false pass means the old unloaded output `Vin*Rb/(Rt+Rb)` met the voltage window but the complete loaded checks failed. These are exact computed counts for the supplied assumptions, not measured accuracy, energy savings or elapsed-time claims. Actual selected circuit values are shown/exported at full calculation precision; UI numbers are rounded.

Small known-answer fixtures: high-impedance meter/scope batch has **one** old-pair failure/false pass; DAQ/panel batch has **two**. All four reviewed nominal plans are feasible. Known loads yield different selected pairs, demonstrating that AI-associated load identity affects the usable output.

## Limitations

The negation challenge incorrectly retrieved **DMM** from a note rejecting the handheld digital multimeter in favor of the low-resistance panel meter. Similarity always retrieves a nearest profile, even for irrelevant text. Four easy synthetic matches do not establish general accuracy. Human identity and impedance review is mandatory.

Only ideal **steady DC, linear resistive loads** and nominal component values are modeled. No resistor tolerance corners, temperature/derating, dynamic ADC sample-and-hold behavior, capacitance, source output impedance, input protection, loading changes, grounding, transient behavior, noise or calibration. The entered power cap applies to the two divider resistors, **not** to the receiving instrument. Removing the load can raise the output substantially; the worksheet does not establish an unloaded-safe operating condition. No high-voltage work, equipment control, automated ordering or construction approval. No physical hardware outcomes were measured.
