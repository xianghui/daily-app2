# Browser-local AI validation notes

Validated in `20261106-12` (Reply Shelf), 2026-11-06. These are project-specific implementation observations, not a replacement for the builder's complete checks.

- Transformers.js 4.3.2 currently selects ONNX Runtime Web's **asyncify** CPU runtime. Copying only `ort-wasm-simd-threaded.mjs` and `.jsep.mjs` does not provide the runtime it actually imports. Inspect the installed package and real network requests, not an assumed older version's file list.
- Provide explicit `env.backends.onnx.wasm.wasmPaths` with matching WASM factory and binary. Vite can emit the binary through `new URL('../node_modules/onnxruntime-web/dist/ort-wasm-simd-threaded.asyncify.wasm', import.meta.url).href`; the exact matched factory can live under public/runtime. The asset's final URL must include the app's Pages base. Do not copy every runtime variant; the tested app needs one factory and one binary.
- Real production browser inference verified quantized `Xenova/all-MiniLM-L6-v2` embeddings with `device:'wasm', dtype:'q8'`, mean pooling and normalization, using four texts per batch. Input/schema checks, task-specific expected labels and exported artifact round trips are separate tests.
- Browser Cache API and HTTP caches are different. Model/WASM cache success does **not** guarantee that a terminated module worker can restart offline. In Chrome, direct worker/module HTTP-cache reuse was inconsistent under forced offline testing. Retain the initialized worker for idle reruns, terminate active workers on cancellation, document offline scope precisely, and test the claimed path. Reply Shelf explicitly caches the local WASM factory too; no full-page offline-reopen promise is made.
- Verify both model-host network failure and subsequent real retry in a fresh context. Error-only mocked Worker/embedding tests should be labeled as fault injection, never counted as successful AI inference.
- A production-only local server started inside deploy/ loses its cwd when root predeploy replaces that directory. Restart it after assembling/publishing, or use a fixed handler directory instead of a removed cwd.
- Chrome full-page screenshots immediately after a large viewport resize can contain compositor tiling. Wait for layout and inspect separate phone-sized page screenshots, including scrolled review/export controls. Overflow assertions alone do not establish visual quality.
- Current create-vite templates may use the folder name as the initial title, not `Vite + React`. Set title by matching the actual `<title>` element. Check the final public title as well as visible headings.
- Final public verification should execute inference on both fixtures and compare downloaded worker/factory/WASM SHA-256 values to the locally validated bundle. Pages `Published` is not the final deployment state; wait for the gh-pages commit to become `built`.
